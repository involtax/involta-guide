# Источник городов

Однократный импорт 2026-11-01 из https://github.com/pensnarik/russian-cities (russian-cities.json).
Источник исходной подборки: Википедия, «Список городов России». Население используется только для выбора размера подборки. Это начальный справочник, не гарантия актуальности или полноты; список и регионы доступны для ручной редакции. Идентичные названия различаются регионом.

# Дополнительные локации

`location-additions.json` — исходные 163 записи из предоставленного пользователем `involta_guide_additions.json`. Все оценки населения помечены непроверенными. Для туристических территорий `service_area_proxy` не импортируется как население: исходная цифра остаётся только в `source_metadata`.

При импорте объединяются Хаджох/Каменномостский и единый Газпром Поляна/Лаура/Альпика. Разделены направление, посёлок и курорт Красная Поляна. Исправлены явно указанные региональные привязки Репино, Комарова, Солнечного, Медовых водопадов и Бирюзовой Катуни. «Сулак» интерпретирован как туристическая локация Сулакский каньон, что отражено в названии. Исходные строки сохранены для проверки.

# Москва

`moscow-districts.json` — 132 района из таблицы https://ru.wikipedia.org/wiki/Районы_Москвы (получено в ходе этой задачи). Используются только названия и принадлежность округам; статистика населения не импортируется. Это внутренний административный справочник.

`moscow-dining-areas.json` — согласованные 20 стартовых гастрономических зон для публичной навигации. Это редакционные территории, их охват не следует считать официальными границами. Четыре существующих района используются повторно; остальные зоны — отдельные записи, связанные с административными районами.

# Грамматические формы

`location-phrases.json` — предварительно подготовленные предложные формы названий с ручными исключениями для ключевых направлений. При подготовке использовался pymorphy3, который не требуется при установке и запуске приложения. Формы доступны для ручного исправления в админке; автоматическая подготовка не гарантирует отсутствия лингвистических ошибок.

Географические координаты и границы из этих файлов не выдумываются. Редактор может добавить проверенный центр и прямоугольник охвата вручную. Редакционные родительские связи не заменяют административную принадлежность.

`location-catalog.json` — resolved geographic catalog exported read-only from the
existing development PostgreSQL during the Python migration. It contains public
location metadata, parent slugs, editorial relations and redirects, not reviews,
restaurant content, user/session data or secrets. It preserves the results of the
original city import, supplied additions and Moscow navigation decisions. Python
seed uses permanent numeric IDs and preserves existing content/geography. Each import replaces nearby_location_ids from this Git file; see docs/LOCATION_IDS.md.
