# Инвольта гид

Общие инструкции о процессе работы: [AGENTS.md](AGENTS.md).
Контекст продукта и карта профильных документов: [docs/PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md).
Авторский подход: [docs/PROJECT_MANIFESTO.md](docs/PROJECT_MANIFESTO.md).
Текущая лента отзывов, GigaAM-only публикация и переход БД: [docs/ADMIN_REVIEWS.md](docs/ADMIN_REVIEWS.md).

Ресторанный справочник России: города, районы, курорты и направления.
**Python 3.13+, FastAPI, Jinja2, HTMX, PostgreSQL 17.** Без Node.js и frontend-сборки.
Модульный монолит; web и worker — два процесса одного приложения, не микросервисы.

## Локальный запуск

Установите [uv](https://docs.astral.sh/uv/) и ffmpeg (нужен ffprobe).

```sh
uv sync --frozen
cp .env.example .env.local
# Задайте DATABASE_URL, TEST_DATABASE_URL, SESSION_SECRET (>=32 символа),
# ADMIN_PASSWORD (>=12), SITE_URL=http://localhost:3000/guide, COOKIE_SECURE=false.
# Для локальной PostgreSQL при необходимости:
docker compose --env-file .env.local -f compose.local.yaml up -d --wait
uv run alembic upgrade head
uv run guide seed
uv run uvicorn involta_guide.main:create_app --factory --host 0.0.0.0 --port 3000 --no-access-log --no-proxy-headers
# В другом терминале:
uv run guide-worker
```

`.env.local` читается через Pydantic Settings и не коммитится. PostgreSQL — единственная
БД. Миграции не запускаются при импорте модулей, просмотре страниц или старте web.
`uv run guide seed` идемпотентно импортирует 1 448 локаций и сохраняет ручные правки.

Адреса: `/guide` → **302** `/guide/`, `/guide/ivanovo`, `/guide/admin`, `/guide/admin/reviews`.
Все API, CSS/JS, health, robots и sitemap находятся внутри `BASE_PATH=/guide`.
`SITE_URL` — полный публичный адрес, например `https://involta.ru/guide`.
Публичные страницы — Jinja HTML с canonical, JSON-LD и noindex для пустых локаций.
Рестораны, в том числе раскрываемые через «Ещё», присутствуют в исходном HTML.
Режим работы и «Ещё» раскрываются без JS; микрофон использует небольшой vanilla widget.

Панорамы хранятся в Git и подключаются по имени `<slug>.avif` без изменения кода.
[Генерация и добавление панорам — технические требования](docs/LOCATION_PANORAMAS.md).

Публичный MCP: `https://involta.ru/guide/mcp`, Streamable HTTP, без авторизации.
Ровно два инструмента — `Location` и `Restaurant`; отзывы входят в карточки.
[Подключение и контракт](docs/MCP.md), страница `/guide/for-agents`, инструкция
`/guide/llms.txt`. Доступность production зависит от развёрнутой версии приложения.

## Архитектура

- `domain/`: чистые dataclasses, состояния и правила. Нет FastAPI/SQLAlchemy/Pydantic.
- `application/`: сценарии, порты UoW/repository, команды внешней валидации.
- `infrastructure/`: SQLAlchemy mappings, PostgreSQL UoW, HTTPX OpenAI, файлы, очередь.
- `web/`: FastAPI handlers, Jinja, HTMX-фрагменты и browser API.

HTTP handlers не выполняют SQL. ORM-модели не используются как доменные сущности.
Синхронные сценарии выполняются FastAPI в thread pool; async используется для ограниченного
чтения загрузки, а блокирующая проверка аудио вынесена из event loop.

## Актуальная страница и отзывы

У страницы одно текущее содержимое: вступление города и рестораны одного владельца.
Вступление, поиск ресторанов и исследование одного места обновляются независимо;
вступление также сохраняется отдельной кнопкой. Диффы ручных правок и наполнения находятся в логах источников; черновиков,
снимков страниц и редакторского голоса нет. Ресторан принадлежит одной локации;
надлокации показывают навигацию по детям. Сохраняются восемь исходных оценок,
факты, телефон, часы, источники и административная звезда Алекса.

Поиск дополняет каталог без удаления отсутствующих мест. Первое исследование
заполняет карточку и оценки вместе. Отдельная переоценка доступна только при
заполненной карточке; дальнейшие факты и оценки обновляются независимо.
`top_limit` ограничивает только первоначальное
отображение на сайте. [Операции, закрытый API и переход БД](docs/INCREMENTAL_CONTENT.md).
Ключ API создаётся штатным деплоем. Агент сам получает его через уже подключённый
GitHub командой `python3 deploy/agent-access.py`; ручной SSH и передача секрета владельцем не нужны.

Сайт автоматически показывает 10 последних успешных исходных текстов GigaAM
города. Parakeet — отдельная строка только в админке. Нет редакционного текста,
ручных решений, привязок и оценок распознавания. Определение сути/ресторана —
следующий этап. Все записи остаются доступны в административной ленте, даже если
публичный лимит их уже не включает. Исходное аудио приватно, технические логи в бете открыты. Админ может удалить отзыв из ленты.
Подробности: [ADMIN_REVIEWS.md](docs/ADMIN_REVIEWS.md).

## OpenAI и очередь

Только `OPENAI_API_KEY` серверного окружения. Ключ не попадает в HTML, browser JS, Git,
настройки сборки или логи. При отсутствии ключа задание получает понятную ошибку.
Обычный просмотр сайта не вызывает AI. HTTPX adapter обеспечивает первоначальное наполнение и
Responses + web search, JSON schema и сохранение usage/модели. Промпт хранится вместе
в логе запуска. Шкала рейтинга: 8 равных факторов, 0–10, half-up округление;
неизвестный фактор не заменяется нулём и не исключается из знаменателя.

Несколько worker забирают задания через `FOR UPDATE SKIP LOCKED`. Lease обновляется
heartbeat; результат проверяет владельца lease и актуальность изменяемого блока. Внешний HTTP-запрос
не удерживает DB-транзакцию. Применение и отметка done атомарны. Сетевые ошибки повторяются
не более `MAX_JOB_ATTEMPTS`, зависшие задания восстанавливаются. SIGTERM останавливает
получение новых задач и позволяет закончить текущую (grace period 240s).

Каждый внешний вызов заранее резервируется в `ai_usage`. `DAILY_AI_CALLS` — жёсткий общий
предел числа вызовов, включая неудачные/неопределённые. `AI_PRICES_JSON` задаёт актуальные
тарифы: `{"model":{"input":USD_per_million,"output":USD_per_million}}`.
Без тарифа стоимость показывается как неизвестная; ограничение числа вызовов действует.
`AI_DAILY_BUDGET_USD` проверяет накопленную оценку при известных тарифах; это не банковский
лимит и не учитывает неизвестные тарифы/все платные инструменты. Дополнительно настройте
лимит бюджета проекта в OpenAI. Никаких платных запросов в тестах.

## Доступ и безопасность

`uv run guide hash-password` создаёт Argon2id hash. Для production используйте
`ADMIN_PASSWORD_HASH`; `ADMIN_PASSWORD` допускается как локальный env bootstrap,
хешируется в памяти, не сохраняется в БД. Admin sessions серверные, в БД только хеши
токенов, есть CSRF, Origin checks, отзыв, HttpOnly/Secure/SameSite cookies и rate limits.

Все роли записывают обычные отзывы. Редакторский голос и персональные секретные ссылки удалены.
Звезда остаётся атрибутом ресторана, голосовой пакет её не меняет. Raw IP, User-Agent
и `guide_visitor` сохраняются сервером и доступны только администратору.

Nginx должен заменять
`X-Forwarded-For`; приложение доверяет ему только от `TRUSTED_PROXY_IPS`. Запускайте
uvicorn с `--no-proxy-headers`, чтобы проверять реальный адрес TCP-соседа. В контейнерах
укажите фактический IP nginx/шлюза, не доверяйте всему Интернету.

## Аудио и хранение

MediaRecorder принимает до 10 МБ и 120 секунд. Backend проверяет сигнатуру,
аудиопоток и длительность через ffprobe. Минимум новой записи — 5 секунд.
Voice хранит аудио вне public; прослушивание требует административной сессии.
Visitor/IP rate limits, bounded queue, исходный epoch и идемпотентный blob/key
сохраняются. Распознавание локальное; OpenAI-анализ отзывов сейчас отключён.

Лимит публичных 10 отзывов не удаляет записи и файлы. Полный административный
сброс локации удаляет её отзывы/аудио/логи через durable manifest и fencing;
служебная миграционная очистка файлов запускается явно:

```sh
uv run guide beta-cleanup-files
uv run guide beta-cleanup-files --execute
```

Резервируйте согласованно обе БД и Voice-аудиотом. Порядок текущего перехода
и отката описан в [ADMIN_REVIEWS.md](docs/ADMIN_REVIEWS.md).

## Проверки

```sh
uv run ruff check src tests migrations
uv run ruff format --check src tests migrations
uv run mypy
uv run pytest -q
```

Тестам нужен отдельный `TEST_DATABASE_URL`. Каждый integration/E2E test создаёт собственную
временную PostgreSQL-схему, не использует production. Playwright: `uv run playwright install
--with-deps chromium` либо `CHROMIUM_PATH=/usr/bin/chromium`. Проверяются legacy migration
сохранность актуальных данных, диффы/FKs, конкурентные правки/worker, fake AI, сессии, CSRF, HTMX,
микрофон, автоматическая GigaAM-only лента, SEO и страницы без JS. Скриншоты: `var/screenshots`.

## Production

Полный автоматический процесс: [docs/DEPLOY.md](docs/DEPLOY.md).
Текущий backend — `http://45.12.67.102:3001`, внешний Nginx основного сайта
проксирует на него `/guide/`. На сервере Guide Nginx не устанавливается.

- `bootstrap-production.yml`: предварительные проверки, Docker из официального
  репозитория, отдельный PostgreSQL Guide, миграции/seed новой БД, контейнеры Guide,
  backup и проверенная настройка Nginx для `/guide/`, HTTPS checks и rollback.
- `deploy-production.yml`: обновления только Guide по SHA/digest с rollback.

Оба запускаются вручную из main через Run workflow, без обязательных reviewers.
Поле SHA необязательно: по умолчанию берётся версия main на момент запуска.
Environment `prod` хранит secrets приложения. PR/push production не меняют.
Используются `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`.
Дополнительные secrets приложения и поддерживаемые схемы Nginx описаны в документации.

Dockerfile — multi-stage build с frozen `uv.lock`, wheel install, отдельным runtime
без uv/dev-инструментов, UID/GID **10001** и healthcheck. Образ подходит для web,
worker и миграций; `ROOT_DIR=/app` задаёт путь к каталогу локаций и миграциям.
Production filesystem read-only, аудио хранится в отдельном persistent volume.

Для переноса **существующей** legacy БД сначала прочитайте
[docs/MIGRATION.md](docs/MIGRATION.md): bootstrap создаёт отдельную новую БД,
а не усыновляет неизвестные контейнеры и данные. Обновления не выполняют
разрушительные миграции или downgrade. Локальная разработка — через `compose.yaml`
и `compose.local.yaml`, отдельно от production.

## Временное публичное наполнение

На пустых страницах доступна кнопка «Запарсить эти данные» без входа. Один клик
ставит независимые вступление и поиск только этой локации, затем исследование новых мест;
дифф каждой операции сохраняется в логе, браузер обновляется после публикации;
после появления данных кнопка исчезает. Повторные клики не создают дубли.
Это временный режим по запросу владельца: [условия и удаление](docs/TEMPORARY_PUBLIC_FILL.md).

## Логи

`/guide/logs` — единая страница: слева один запуск наполнения, справа вся цепочка
его запросов и выбранный полный лог. Отдельная переоценка — отдельный запуск.
Администратор видит все запросы; публично доступны только разрешённые логи наполнения.
Адрес и ключ в БД — город + номер: `/guide/logs/ivanovo/1`. Переименование slug
обновляет сохранённые пути логов каскадно. [Сохранение данных и доступ](docs/LOGS.md).

Для публичного первоначального наполнения также доступен `/guide/logs` без входа,
со ссылкой из пустой страницы города. Закрытые задания и отзывы туда не попадают.

Новые вступления генерируются одним предложением от 50 до 100 символов; прежний текст
модели не передаётся. [Примеры и мобильные измерения](docs/design/short-city-introductions/README.md).

Модель и три независимых промпта сохраняются в «Настройках наполнения»
(`/guide/admin/settings/filling`) без создания заданий. Модель фиксируется
в каждом задании. Ручной повтор создаёт новый запрос и лог вида
`/guide/logs/ivanovo/2`; прежние логи сохраняются. Для заполненной страницы
результат повторного запроса сразу обновляет актуальные данные после проверки.

Временные решения и совместимость, которые планируется удалить, ведём в
[реестре легаси](docs/LEGACY_REMOVAL.md): код, причины сохранения и условия удаления.

## Отдельный Voice-сервис

Voice имеет собственные БД, аудио, два локальных ASR и worker. Guide принимает
receipt/primary events через outbox/inbox и автоматически показывает последние
10 GigaAM-текстов города. По умолчанию новый путь выключен (`VOICE_ENABLED=false`).
[Контракт](docs/VOICE_API.md), [локальный запуск и откат](docs/VOICE_RUNBOOK.md),
[этапы и проверки](docs/VOICE_IMPLEMENTATION.md). Production-деплой отдельно.
## Полнота поиска ресторанов

Число карточек до «Ещё» не ограничивает поиск. Все найденные кандидаты учитываются
со статусом и причиной, пропущенные карточки оценённых кандидатов отклоняются,
неполный поиск явно показывается в админке и логах. Описания очищаются от ссылочной
разметки с сохранением источников. [Контракт и пример Переславля](docs/GENERATION_QUALITY.md).

Адреса разделов и инструкция проверки: [ADMIN_ROUTES.md](docs/ADMIN_ROUTES.md).
Первичное наполнение запускается на пустой публичной странице, повтор — в конкретном
логе. Массовой генерации и запуска из карточки города нет.

Единый интерфейс админки, причины прежнего разнобоя и матрица ручной проверки:
[ADMIN_DESIGN.md](docs/ADMIN_DESIGN.md).

### Voice runtime

Voice остаётся отдельным backend: контейнер `voice` объединяет API и доставку
результатов в Guide, `voice-worker` выполняет ASR/анализ. PostgreSQL и база общие;
таблицы Voice находятся в схеме `voice`. [Схема, переход и остановка](docs/VOICE_RUNTIME.md).
