# Инвольта гид

[![Checks](https://github.com/involtax/involta-guide/actions/workflows/ci.yml/badge.svg)](https://github.com/involtax/involta-guide/actions/workflows/ci.yml)

**MVP · 0.1.0** · [Границы MVP](docs/MVP.md) · [Разработка](CONTRIBUTING.md) · [Безопасность](SECURITY.md) · [Изменения](CHANGELOG.md)

Справочник ресторанов по городам России. Публичные HTML-страницы, редакционная админка, голосовые отзывы и очередь предложений ИИ. **Next.js / React / TypeScript / PostgreSQL 17.** Аудио хранится в закрытом серверном каталоге.

## Быстрый старт

Нужны Node.js из `.nvmrc` и Docker Compose (либо готовый PostgreSQL).

```sh
npm ci
npm run setup:local
npm run db:up
npm run db:migrate
npm run db:seed
# Задайте ADMIN_PASSWORD (от 12 символов) в .env.local.
npm run dev
# В другом терминале:
npm run worker
```

`setup:local` однократно создаёт случайный пароль локального PostgreSQL, `DATABASE_URL`, `TEST_DATABASE_URL` и `SESSION_SECRET` в игнорируемом `.env.local`, сохраняя существующие значения. Он не создаёт и не копирует OpenAI-ключ. Для своего PostgreSQL задайте `DATABASE_URL` через окружение сервера и пропустите `setup:local` / `db:up`.

Сайт: `/guide`, город: `/guide/ivanovo`, админка: `/admin`. Для HTTPS задайте `SITE_URL=https://involta.ru` и `COOKIE_SECURE=true`. `SITE_URL` должен совпадать с внешним origin, включая порт локальной разработки: он используется для защиты запросов, canonical и sitemap. Микрофон работает по HTTPS или на localhost.

## PostgreSQL и миграции

- Единственный источник подключения — серверный `DATABASE_URL`. Приложение, воркер и команды миграции должны использовать одну БД.
- Миграции в `migrations/*.sql`, команда `npm run db:migrate`. Применённые имена и контрольные суммы сохраняются в `schema_migrations`. Применённый файл не редактируют: добавляют следующий.
- Схема не создаётся во время HTTP-запросов и сборки. Перед первым запуском выполните миграции и импорт городов.
- `npm run db:seed` однократно импортирует 1134 города из `data/cities.json`; источник указан в `data/SOURCE.md`. Повторный запуск сохраняет ручные изменения и текущий промпт.
- Миграции и импорт защищены advisory locks. Версии одной страницы создаются под блокировкой строки города. Воркеры забирают разные задания через `FOR UPDATE SKIP LOCKED`; частичные уникальные индексы исключают дубли активных заданий.
- Контент и результаты ИИ хранятся в JSONB, связи защищены внешними ключами. Транзакционные запросы выполняются через одно подключение.
- Для managed PostgreSQL используйте TLS-параметры провайдера в `DATABASE_URL` и штатное доверие CA; не отключайте проверку сертификатов.

Локальная БД слушает только `127.0.0.1:5432`, данные сохраняются в Docker volume `postgres-data`. `docker compose --env-file .env.local down` останавливает БД без удаления данных. Не используйте `down -v`, если данные нужны.

## OpenAI и очередь

Задайте **только серверную переменную `OPENAI_API_KEY`** через платформу деплоя или менеджер секретов, отдельно для приложения и воркера. Для сборки и CI ключ не нужен. Модели по умолчанию: `gpt-4.1` с веб-поиском для наполнения и `gpt-4o-mini-transcribe` для аудио; доступность зависит от аккаунта API.

Все API-вызовы находятся в backend-модуле `lib/ai.mjs`; Next.js использует обёртку `server-only`. Ключ не передаётся React-компонентам, HTML, JSON-ответам, localStorage, `NEXT_PUBLIC_*` или настройкам сборки. При отсутствии ключа задание получает понятную ошибку для редактора. Заголовки авторизации и тела ошибок API не логируются. Скрипты сохраняют штатные proxy и TLS-настройки.

Вкладка «Наполнение»: сохранить промпт → выбрать один город → поставить задание → выполнить воркером или кнопкой «Выполнить одно задание» → проверить черновик → опубликовать. Массовый запуск создаёт отдельные платные задания. Ошибки видны в очереди и повторяются вручную. Прерванные задания старше 20 минут помечаются ошибкой при следующем проходе воркера.

## Страницы и публикация

Город, база ресторанов, черновик и публичная версия разделены. Каждое сохранение создаёт версию **страницы**: содержимое, источник, дату и промпт/модель конкретного запуска. Отдельного журнала промптов нет: редактор хранит текущую инструкцию, задания фиксируют её на момент запуска.

Черновики не влияют на сайт. Старую версию можно восстановить в новый черновик либо опубликовать напрямую. Публичные страницы содержат готовый серверный HTML, canonical, sitemap, Restaurant/ItemList JSON-LD. Пустые города имеют noindex и не включаются в sitemap. Фото и средний чек в MVP не используются.

## Отзывы и модерация

Только микрофон: до 2 минут и 10 МБ. Сохраняются **все** записи: аудио, cookie-ID браузера, SHA-256 аудио, HMAC IP, user-agent, расшифровка, результат ИИ и решения редактора. Reverse proxy должен заменять входящий `X-Forwarded-For`. Cookie и user-agent — признаки браузера, не надёжный отпечаток устройства.

Каждая осмысленная запись после обработки создаёт один или несколько отзывов с текстом либо оценок без текста — по упомянутым ресторанам. Дополнительно предлагаются уместные правки и новые рестораны. Тональность и рекомендация: −10…10; оценка: 0…10. Неизвестное — null. Уверенность извлечения не подтверждает правдивость рассказа.

Одобрение, учёт во внутренней статистике, перенос предложения в черновик и публикация — разные операции. Отклонённые и фродовые записи сохраняются, но исключаются из внутренних средних. Порядок топа задаёт редактор.

Экран модерации: аудио, расшифровка, атрибуты, цитаты, «было → станет», похожие записи. Косвенные сигналы: одинаковое аудио, общий cookie/IP, лексическое сходство текстов. Анализируются последние 2000 записей. Нет автоматических блокировок и CAPTCHA; несогласие с большинством не считается доказательством фрода. Посетитель видит статус обработки по cookie своего браузера.

## Проверки и CI

```sh
npm run check
npm test
npm run build
npm run test:e2e
```

Тестам нужен `TEST_DATABASE_URL`: они создают отдельные случайные схемы и удаляют **только эти схемы** после выполнения. В production используйте отдельную тестовую БД и пользователя с правом создавать схемы. При отсутствии адреса тесты завершаются понятной ошибкой, а не подменяют PostgreSQL другой БД.

E2E поднимает production-сервер с временной схемой и каталогом аудио. Использует Chromium: системный `/usr/bin/chromium`, браузер Playwright или `CHROMIUM_PATH`. Проверяет вход, защиту API, черновик/публикацию, HTML SEO, запись с тестового микрофона, cookie-историю, модерацию и отсутствие утечки контрольного секрета. Тестовые рестораны не попадают в рабочую схему. Скриншоты — `var/screenshots/`.

Workflow `Checks` поднимает PostgreSQL 17, проверяет типы, интеграционные тесты, сборку и E2E при push в `main` и Pull Request. Production-секреты в CI не передаются; реальные OpenAI-вызовы не выполняются. CI не развёртывает сайт.

## Развёртывание

```sh
npm ci
npm run db:migrate
npm run db:seed
npm run build
npm start
# Отдельный процесс / сервис:
npm run worker
```

Передайте `DATABASE_URL`, `OPENAI_API_KEY`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `SITE_URL` и `COOKIE_SECURE=true` через окружение сервера. Рабочему пользователю БД достаточно доступа к данным; миграции выполняйте отдельным пользователем с DDL-правами. Миграции применяются перед обновлением процессов.

Резервируйте PostgreSQL (`pg_dump` либо managed backups) и `var/audio/` вместе. `DATA_DIR` меняет расположение аудио, а не БД. Несколько воркеров могут использовать одну очередь PostgreSQL; для нескольких серверов потребуется общее хранилище аудио или S3.

Reverse proxy направляет `/guide`, `/admin`, `/api`, `/_next`, `/sitemap.xml`, `/robots.txt` в приложение. Перед подключением к существующему involta.ru нужно согласовать возможные конфликты служебных маршрутов. Админка использует один пароль и сессию на 8 часов. До публичного запуска нужны правила обработки аудио, сроки хранения и резервное копирование. Автоматическое удаление аудио и автоматическая публикация не включены.
