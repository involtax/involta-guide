# Инвольта гид

[![Checks](https://github.com/involtax/involta-guide/actions/workflows/ci.yml/badge.svg)](https://github.com/involtax/involta-guide/actions/workflows/ci.yml)

**MVP · 0.1.0** · [Границы MVP](docs/MVP.md) · [Разработка](CONTRIBUTING.md) · [Безопасность](SECURITY.md) · [Изменения](CHANGELOG.md)

Справочник ресторанов по городам, районам, курортам и туристическим направлениям России. Публичные HTML-страницы, редакционная админка, голосовые отзывы и очередь предложений ИИ. **Публичный сайт: Node.js + HTML/CSS/JavaScript. Админка: Next.js / React / TypeScript. База: PostgreSQL 17.** Аудио хранится в закрытом серверном каталоге.

## Быстрый старт

Нужны Node.js из `.nvmrc` и Docker Compose (либо готовый PostgreSQL).

```sh
npm ci
npm run setup:local
npm run db:up
npm run db:migrate
npm run db:seed
# Задайте ADMIN_PASSWORD (от 12 символов) в .env.local.
npm run dev
# В другом терминале:
npm run worker
```

`setup:local` однократно создаёт случайный пароль локального PostgreSQL, `DATABASE_URL`, `TEST_DATABASE_URL` и `SESSION_SECRET` в игнорируемом `.env.local`, сохраняя существующие значения. Он не создаёт и не копирует OpenAI-ключ. Для своего PostgreSQL задайте `DATABASE_URL` через окружение сервера и пропустите `setup:local` / `db:up`.

Сайт: `/guide`, город: `/guide/ivanovo`, админка: `/guide/admin`. Для HTTPS задайте `SITE_URL=https://involta.ru/guide` и `COOKIE_SECURE=true`. `SITE_URL` должен содержать полный публичный адрес приложения, включая `/guide` и порт локальной разработки: он используется для защиты запросов, canonical и sitemap. Микрофон работает по HTTPS или на localhost.

## PostgreSQL и миграции

- Единственный источник подключения — серверный `DATABASE_URL`. Приложение, воркер и команды миграции должны использовать одну БД.
- Миграции в `migrations/*.sql`, команда `npm run db:migrate`. Применённые имена и контрольные суммы сохраняются в `schema_migrations`. Применённый файл не редактируют: добавляют следующий.
- Схема не создаётся во время HTTP-запросов и сборки. Перед первым запуском выполните миграции и импорт городов.
- `npm run db:seed` сохраняет базу 1134 городов и добавляет пользовательские локации, иерархию и московские зоны; источники указаны в `data/SOURCE.md`. Повторный запуск сохраняет ручные изменения и текущий промпт.
- Миграции и импорт защищены advisory locks. Версии одной страницы создаются под блокировкой строки города. Воркеры забирают разные задания через `FOR UPDATE SKIP LOCKED`; частичные уникальные индексы исключают дубли активных заданий.
- Контент и результаты ИИ хранятся в JSONB, связи защищены внешними ключами. Транзакционные запросы выполняются через одно подключение.
- Для managed PostgreSQL используйте TLS-параметры провайдера в `DATABASE_URL` и штатное доверие CA; не отключайте проверку сертификатов.

Локальная БД слушает только `127.0.0.1:5432`, данные сохраняются в Docker volume `postgres-data`. `docker compose --env-file .env.local down` останавливает БД без удаления данных. Не используйте `down -v`, если данные нужны.

## OpenAI и очередь

Задайте **только серверную переменную `OPENAI_API_KEY`** через платформу деплоя или менеджер секретов, отдельно для приложения и воркера. Для сборки и CI ключ не нужен. Модели по умолчанию: `gpt-4.1` с веб-поиском для наполнения и `gpt-4o-mini-transcribe` для аудио; доступность зависит от аккаунта API.

Все API-вызовы находятся в backend-модуле `lib/ai.mjs`; Next.js использует обёртку `server-only`. Ключ не передаётся React-компонентам, HTML, JSON-ответам, localStorage, `NEXT_PUBLIC_*` или настройкам сборки. При отсутствии ключа задание получает понятную ошибку для редактора. Заголовки авторизации и тела ошибок API не логируются. Скрипты сохраняют штатные proxy и TLS-настройки.

Вкладка «Наполнение»: сохранить промпт → выбрать одну локацию → поставить задание → выполнить воркером или кнопкой «Выполнить одно задание» → проверить черновик → опубликовать. Массовый запуск создаёт отдельные платные задания. Ошибки видны в очереди и повторяются вручную. Прерванные задания старше 20 минут помечаются ошибкой при следующем проходе воркера.

## Страницы и публикация

Локация, база ресторанов, черновик и публичная версия разделены. Каждое сохранение создаёт версию **страницы**: содержимое, источник, дату и промпт/модель конкретного запуска. Отдельного журнала промптов нет: редактор хранит текущую инструкцию, задания фиксируют её на момент запуска.

Черновики не влияют на сайт. Старую версию можно восстановить в новый черновик либо опубликовать напрямую. Публичные страницы содержат готовый серверный HTML, canonical, sitemap, Restaurant/ItemList JSON-LD. Пустые локации имеют noindex и не включаются в sitemap. Фото и средний чек в MVP не используются.

## Отзывы и модерация

Только микрофон: до 2 минут и 10 МБ. Сохраняются **все** записи: аудио, cookie-ID браузера, SHA-256 аудио, HMAC IP, user-agent, расшифровка, результат ИИ и решения редактора. Reverse proxy должен заменять входящий `X-Forwarded-For`. Cookie и user-agent — признаки браузера, не надёжный отпечаток устройства.

Каждая осмысленная запись после обработки создаёт один или несколько отзывов с текстом либо оценок без текста — по упомянутым ресторанам. Дополнительно предлагаются уместные правки и новые рестораны. Тональность и рекомендация: −10…10; оценка: 0…10. Неизвестное — null. Уверенность извлечения не подтверждает правдивость рассказа.

Одобрение, учёт во внутренней статистике, перенос предложения в черновик и публикация — разные операции. Отклонённые и фродовые записи сохраняются, но исключаются из внутренних средних. Порядок топа задаёт редактор.

Экран модерации: аудио, расшифровка, атрибуты, цитаты, «было → станет», похожие записи. Косвенные сигналы: одинаковое аудио, общий cookie/IP, лексическое сходство текстов. Анализируются последние 2000 записей. Нет автоматических блокировок и CAPTCHA; несогласие с большинством не считается доказательством фрода. Посетитель видит статус обработки по cookie своего браузера.

## Проверки и CI

```sh
npm run check
npm test
npm run build
npm run test:e2e
```

Тестам нужен `TEST_DATABASE_URL`: они создают отдельные случайные схемы и удаляют **только эти схемы** после выполнения. В production используйте отдельную тестовую БД и пользователя с правом создавать схемы. При отсутствии адреса тесты завершаются понятной ошибкой, а не подменяют PostgreSQL другой БД.

E2E поднимает production-сервер с временной схемой и каталогом аудио. Использует Chromium: системный `/usr/bin/chromium`, браузер Playwright или `CHROMIUM_PATH`. Проверяет вход, защиту API, черновик/публикацию, HTML SEO, запись с тестового микрофона, cookie-историю, модерацию и отсутствие утечки контрольного секрета. Тестовые рестораны не попадают в рабочую схему. Скриншоты — `var/screenshots/`.

Workflow `Checks` поднимает PostgreSQL 17, проверяет типы, интеграционные тесты, сборку и E2E при push в `main` и Pull Request. Production-секреты в CI не передаются; реальные OpenAI-вызовы не выполняются. CI не развёртывает сайт.

## Развёртывание

```sh
npm ci
npm run db:migrate
npm run db:seed
npm run build
npm start
# Отдельный процесс / сервис:
npm run worker
```

Передайте `DATABASE_URL`, `OPENAI_API_KEY`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `SITE_URL` и `COOKIE_SECURE=true` через окружение сервера. Рабочему пользователю БД достаточно доступа к данным; миграции выполняйте отдельным пользователем с DDL-правами. Миграции применяются перед обновлением процессов.

Резервируйте PostgreSQL (`pg_dump` либо managed backups) и `var/audio/` вместе. `DATA_DIR` меняет расположение аудио, а не БД. Несколько воркеров могут использовать одну очередь PostgreSQL; для нескольких серверов потребуется общее хранилище аудио или S3.

Reverse proxy направляет только `/guide` и `/guide/*` в отдельный контейнер. Админка, API и файлы сборки используют тот же префикс, остальные пути involta.ru обслуживает основной сайт. Админка использует один пароль и сессию на 8 часов. До публичного запуска нужны правила обработки аудио, сроки хранения и резервное копирование. Автоматическое удаление аудио не включено. Обычные отзывы публикуются вручную; авторизованные команды Алекса применяются автоматически.

## Система оценки ресторанов

Текущий базовый промпт: [`data/prompts/restaurant-ranking-v1.txt`](data/prompts/restaurant-ranking-v1.txt). Восемь факторов: еда, стабильность, самобытность, связь с городом, атмосфера, сервис, оправданность цены и целесообразность отдельного визита. Каждый имеет вес 12,5%, шкалу 0–10 и отдельное обоснование/уверенность/источники. Итог — сумма / 8, округлённая до двух знаков. Отсутствующий фактор означает `null` для итога, а не усреднение по оставшимся.

ИИ возвращает до десяти кандидатов в `rankingReport`, а сервер независимо пересчитывает баллы и порядок. Короткая публичная подборка соответствует лидерам расчёта. Полный отчёт сохраняется в JSONB версии страницы и доступен в редакторе города. Ручное сохранение через редактор сохраняет отчёт. Изменение файла базового промпта не перезаписывает текущую инструкцию в БД автоматически: существующий промпт редактируется в админке.

`tests/fixtures/ivanovo-calibration.json` содержит условные оценки из обсуждения для проверки арифметики. Они не являются исследованием заведений и не используются для наполнения рабочей БД.

## Локации и надлокации

Внедрены отдельные страницы районов, посёлков, курортов и туристических территорий. Газпром Поляна — одна локация; Лаура и Альпика доступны как её дополнительные названия. У Москвы 20 публичных гастрономических зон, административные районы остаются внутренним справочником. У Сочи и Красной Поляны есть отдельные направления и дочерние территории. [Полное описание модели и обновления](docs/locations.md).

В админке можно управлять типом, родителем, связанными местами, дополнительными названиями, формой заголовка, видимостью, лимитом подборки, координатами и охватом. Общие подборки собираются из существующих ресторанов без копий в БД. Публикация ручная. Смена адреса сохраняет постоянное перенаправление.

При обновлении прежней городской версии сначала остановите приложение и воркер: миграция переименовывает `cities` в `locations`, сохраняя ID, отзывы и версии. После миграций и импорта соберите и запустите новую версию. Не запускайте старый код на новой схеме.

### Телефоны, часы работы и Алекс

Телефон хранится в `restaurants.phone` в международном формате. Без телефона нельзя публиковать новую версию; старые опубликованные версии продолжают открываться. Часы — `opening_hours`: IANA timezone, семь дней Пн–Вс, несколько интервалов в день, исключения по датам. Неизвестный режим не означает «закрыто». Первые `top_limit` карточек видны сразу, остальные утверждённые карточки доступны через «Ещё» и присутствуют в HTML.

Предложения телефонов: `/guide/admin/contacts`. Повторы группируются, видны число браузеров, сетей, одобренных сообщений и фродовых записей. Это сигналы, не доказательство правильности. Новое значение вручную принимается через исходный отзыв и сохраняется черновиком. Публикация отдельная.

Алекс входит по `/guide/?СЕКРЕТ`. Установите `ALEX_SECRET` через менеджер секретов (случайные 32 байта, например `openssl rand -hex 32`), не вставляйте значение в Git. Ссылка выдаёт HttpOnly-сессию на 30 дней и перенаправляет на `/guide/` без токена. Настройте прокси так, чтобы для `/guide/` не логировались query string; не передавайте ссылку сторонней аналитике. В production нужны HTTPS и `COOKIE_SECURE=true`.

`/guide/alex` показывает сессии и голосовые изменения с исходной записью и «было / стало». Администратор может завершить все сессии; при утечке также замените `ALEX_SECRET` в секретах. Звезда — отдельное поле, доступное только авторизованным командам Алекса, а не обычным отзывам или редакторскому JSON. Она не даёт бонуса рейтингу.

Команды Алекса обрабатывает тот же серверный воркер (нужен OpenAI API для распознавания и разбора). Изменение и публикация атомарны, история версий и связь с записью сохраняются. Комментарий без команды одобряется и сохраняется без переписывания статьи. Неполная или неоднозначная команда, отсутствующий телефон либо параллельная правка приводят к записи ошибки в журнале, без частичной публикации. Если существует неопубликованный редакторский черновик, сначала завершите работу с ним: голосовая команда не публикует его случайно. Откат доступен через историю страницы в админке.

### Отдельный контейнер под involta.ru/guide

Публичный адрес приложения: `SITE_URL=https://involta.ru/guide`. `NEXT_PUBLIC_BASE_PATH=/guide` задаётся при сборке Next.js и Docker image; после его изменения нужна пересборка. Весь сайт приложения, включая админку `/guide/admin`, API `/guide/api`, журнал `/guide/alex`, sitemap `/guide/sitemap.xml` и файлы `/guide/_next`, находится под этим префиксом. Основной сайт involta.ru обслуживается отдельно.

Соберите образ: `docker build --build-arg NEXT_PUBLIC_BASE_PATH=/guide -t involta-guide .`. Передайте серверные секреты и `DATABASE_URL` при запуске через env/менеджер секретов. Веб-процесс (HTML-сервер и обработчик админки/API): `npm start`; отдельный воркер из того же образа: `npm run worker`. Оба процесса должны использовать одну PostgreSQL и общий постоянный том `/app/var` для аудио. Перед обновлением выполните `npm run db:migrate` в контейнере с доступом к БД.

Включите `deploy/nginx-guide.conf` в существующий server-блок involta.ru. Nginx и контейнер должны находиться в общей Docker-сети; upstream `involta-guide:3000` замените на действительное имя контейнера при необходимости. `proxy_pass` сохраняет `/guide`, не обрезает его. Остальные location основного сайта не меняются. Секрет Алекса открывается как `https://involta.ru/guide/?СЕКРЕТ`; значение берётся из `ALEX_SECRET`, после открытия адрес очищается. Логирование query string для этого пути отключено в примере.

Для локального запуска используйте `SITE_URL=http://localhost:3000/guide`; порт контейнера 3000, публичный HTTPS завершает nginx. Cookie ограничены путём `/guide`.

Корневой адрес `/guide` перенаправляется **302** на `/guide/` с сохранением query string. Это правило есть в nginx и в приложении при прямом доступе к контейнеру. Автоматический редирект Next.js в обратную сторону отключён.

### Публичный сайт без React

`npm start` запускает `scripts/server.mjs`: сервер Node.js отдаёт публичные страницы напрямую из HTML-шаблонов `lib/public-html.mjs` и `lib/public-pages.mjs`. Публичные страницы не проходят через React/Next.js, не содержат RSC/гидратацию и не загружают `/_next`-скрипты. HTML собирается по опубликованной версии из PostgreSQL; это серверный HTML на запрос, а не статические файлы, сгенерированные заранее. Публикация и смена звезды видны при следующем запросе.

Админка `/guide/admin`, журнал `/guide/alex` и API обслуживаются обработчиком Next.js в том же веб-процессе. React сохранён для административного интерфейса. Для запуска используйте `npm start`, а не `next start`: последний не запускает публичный HTML-сервер. Dockerfile уже использует `npm start`.

Расписание и «Ещё» раскрываются нативным `<details>` без JavaScript. Отдельный модуль `public/hours.js` обновляет статус часов в браузере; исходное состояние также присутствует в серверном HTML.

Голосовой виджет — самостоятельный встраиваемый `public/widget.js`, доступный по `/guide/widget.js`, без React и npm-зависимостей в браузере. Контейнер задаёт `data-location-id` и `data-api-base`; скрипт использует только HTTP API записи/истории. Запись, воспроизведение, cookie-история и уведомления об ошибках работают через браузерные API. Сам виджет не является микросервисом: приём аудио пока использует общий API и PostgreSQL, обработка идёт отдельным процессом `npm run worker`. Отдельное развёртывание голосового backend потребует выделения хранилища/доступа к очереди и маршрутизации, сейчас этого нет.
