# GigaAM / Parakeet: локальная бета распознавания

Каждая новая запись распознаётся **обеими моделями**, последовательно, на CPU.
Первый основной текст сохраняет GigaAM; Parakeet сохраняет независимый вариант.
Это технический выбор источника на время беты, не вывод о качестве моделей.
Если GigaAM завершился ошибкой, успешный Parakeet сохраняет основной текст.
Ошибка сравнения не блокирует основной отзыв или его модерацию. Текст сохраняется
до необязательного анализа. Второй результат не создаёт второй отзыв и не запускает
дополнительные изменения страницы. Смена победителя будет отдельным решением после
живого тестирования; старые тексты от этого не переписываются.

Аудио не отправляется в OpenAI. OpenAI используется только для необязательного
анализа сохранённого текста.
Голос администратора — обычный отзыв в той же очереди Voice; права, cookie и
модерация остаются в Guide. Новая ASR база не нужна: результаты
сравнения, оценки и задания хранятся в существующей отдельной PostgreSQL Voice.

Attribution: NVIDIA, Parakeet TDT 0.6B v3, ONNX conversion by istupakov.
Мы используем преобразованные и квантованные int8 веса, не изменяем исходную
модель для обучения. Ссылки на авторов, модель и лицензию приведены выше;
README/model cards сохраняются с весами. GigaAM и Silero также сохраняют LICENSE.txt.

Движок — `onnx-asr[cpu,hub]`, не PyTorch/NeMo сервис. Версии библиотек закреплены
`uv.lock`; код моделей с Hugging Face не исполняется. PyAV декодирует WAV, Ogg,
WebM, MP4 в mono float32 16 kHz. Для обеих моделей одинаковые исходные bytes,
декодирование и [Silero VAD](https://huggingface.co/istupakov/silero-vad-onnx)
ревизии `b3e3ee3cce4c11ceb63b1a0b229d916069c1ddf6`, speech chunks ≤20 с,
минимальная тишина 500 мс, batch=1. Сохраняются SHA исходного файла и PCM,
текст/сегменты, настройки, время и ревизии. Без речи — ошибка, без выдуманного отзыва.

## Установка

```bash
uv sync --frozen --extra voice-local
# .env.voice: отдельная БД/роль Voice и VOICE_SERVICE_SECRET как в примере
uv run voice migrate
uv run voice prepare-model
uv run voice-worker
```

Настройки: `VOICE_ASR_BETA_ENABLED=true`, `VOICE_TRANSCRIPTION_MODEL=gigaam`,
`VOICE_ASR_CPU_THREADS=2`, `VOICE_ASR_MODELS_DIR=var/asr-models`.
Подготовка скачивает обе модели и VAD по точным ревизиям. Serving использует только
локальные файлы; нет автоматической загрузки или облачного fallback.
Compose готовит named volume `asr-models` отдельным завершающимся заданием и затем
монтирует его read-only в Voice worker. API/web/Guide не загружают модели.
Исполнитель держит в памяти только одну ASR модель; перед сменой освобождает её.
В очереди основной текст приоритетнее вторичного сравнения. Прерванный локальный
этап можно повторить до трёх попыток; сохранённый raw response используется без
нового inference. Для неизвестного исхода платного анализа прежний запрет слепого
повтора сохраняется. Результаты и аудио автоматически не удаляются.

## Прогон всех сохранённых записей

Команды выполняются **на сервере с сохранёнными аудио**, после согласованного
перехода beta core. Не копировать реальные записи в GitHub/CI. `voice asr-backfill`
охватывает normal Voice submissions, включая ещё не импортированные в Guide.
Повтор переиспользует пару с теми же настройками. Отдельного Guide inventory,
архива и внутренних транскрипций Guide больше нет; старый несовместимый корпус
очищается только явным переходом из [BETA_CORE_RUNBOOK.md](BETA_CORE_RUNBOOK.md).

Для локальной установки:

```bash
uv run voice asr-backfill                   # инвентаризация без записи
uv run voice asr-backfill --execute          # оставшиеся записи Voice
uv run voice asr-report                     # JSON сводка
```

Production использует существующий project `involta-guide-production` и Compose
активного release; не создавать другой проект или пустые volumes. В операторском
окружении должны быть заданы несекретные `DEPLOY_ROOT`, `RELEASE_SHA` и `IMAGE_REF`
текущего релиза, как при штатном запуске. Обе приватные env-file нужны для
интерполяции; вывод `docker compose config` с секретами не сохранять.

```bash
# Функция только запускает команды внутри уже работающих контейнеров.
voice_compose() {
  docker compose --project-name involta-guide-production \
    --env-file "$DEPLOY_ROOT/.env.production" --env-file "$DEPLOY_ROOT/.env.voice" \
    -f "$DEPLOY_ROOT/releases/$RELEASE_SHA/compose.yaml" \
    -f "$DEPLOY_ROOT/releases/$RELEASE_SHA/compose.voice.yaml" "$@"
}
voice_compose exec -T voice-api voice asr-backfill
voice_compose exec -T voice-api voice asr-backfill --execute
voice_compose exec -T voice-api voice asr-report
```

Для host-профиля в активном release уже установлены соответствующие шаблоны;
та же функция использует правильные файлы.
Нужно проверить отсутствие missing_audio / SHA mismatch / errors, дождаться обеих
моделей у всех доступных реальных записей. Отсутствующее аудио восстановить из
резервной копии: текст не заменяет исходную запись для оценки ASR. Технические
`deployment-smoke` записи и fake-ответы не участвуют в итоговом сравнении.

## Живой тест и выбор одной модели

На существующем экране отзыва администратор слушает исходное аудио, сравнивает
оба текста, сохраняет предпочтение, правильную расшифровку и заметку. Такой же
блок есть у ещё не доставленных записей, включая ошибки. Оценка имеет версию,
idempotency UUID, digest сравниваемых результатов и журнал с сессией администратора.
Повторный ASR-прогон запускается явно; предыдущие варианты остаются доступны.
Эта оценка не одобряет пакет отзыва и не меняет страницу.

В `voice asr-report` берётся последняя пара на одну запись с текущими закреплёнными
настройками. Повторы не раздувают выборку; fake-записи исключены. Сводка показывает
успехи/ошибки/ожидающие этапы, предпочтения, скорость и взвешенные WER/CER.
WER — число вставок, удалений и замен слов / число слов в ручном эталоне; CER —
аналогично для символов без пробелов. Регистр, пунктуация и ё/е нормализуются;
числа словами/цифрами специально не уравниваются. Без ручного эталона метрики null.
Старая машинная расшифровка не считается правильным ответом.

В бете нужны реальные микрофоны/браузеры, тишина/шум, разные голоса, названия
заведений и городов, телефоны/числа, короткие и длинные отзывы, записи администраторов как обычные отзывы.
Отдельно оценить ошибки имён/чисел, сохранность отзыва, очередь и задержку. Модель
не выбирается автоматически по одной метрике. После согласованного выбора:
выбрать основной ключ в настройках Voice, установить `VOICE_ASR_BETA_ENABLED=false`
и перезапустить worker/API. Новые записи получат один ASR этап; прошлые пары,
оценки и аудио сохранятся. Явный исторический прогон обеих моделей остаётся доступен;
для него сохранять обе подготовленные модели на диске.

## Ресурсы и границы проверки

Цель — VPS 8 GiB RAM, 2 vCPU, CPU int8; GPU не требуется. Worker ограничен
3 GiB / 1.5 CPU, остальные ресурсы остаются Guide/PostgreSQL/API. Нужно минимум
6 GiB свободного места под веса/кеш подготовки плюс рост аудио и резервные копии.
RAM сама по себе не ускоряет вычисления: CPU влияет на очередь; второй проход
добавляет работу на запись. Две модели одновременно в память не загружаются.

На машине разработки обе реальные модели уже выполнили inference на одном
синтетическом русском eSpeak-файле 9.12 с: GigaAM около 2.14 с с загрузкой
(0.72 с inference), Parakeet 4.30 с (1.13 с inference), peak RSS процесса 1244 MiB.
Это smoke декодера/загрузки, **не проверка качества на живом русском голосе**.
Обе модели ошибались на синтетическом голосе. Эти цифры не являются замером VPS.
Реальный production-корпус этим изменением ещё не обработан; запуск после отдельной
команды на production. Не мержить и не деплоить автоматически ради этого документа.


Дополнительно проверен настоящий inference в Docker без сети, от пользователя
10001, с read-only root/models и лимитом 3 GiB / 1.5 CPU: на синтетическом Ogg
9.12 с GigaAM 2.93 с, Parakeet 4.37 с (время вместе с загрузкой), peak RSS 1272 MiB.
Смена GigaAM → Parakeet → GigaAM прошла в том же процессе, PCM SHA совпали;
двухсекундную тишину обе модели отклонили. Это проверка запуска в ограниченном
контейнере; качество живого голоса и характеристики VPS ею не подтверждаются.

## Первый production-запуск

Защищённый workflow `Deploy Voice production` выполняет весь запуск одной
операцией: проверяет VPS 8 GiB, резервирует Guide DB/audio и существующие Voice
DB/audio, настраивает отдельные приватные credentials, выкладывает проверенный
SHA со всеми процессами, скачивает обе модели, ждёт health, включает gateway и
ставит сохранённые записи на сравнение. Отдельный feature-off релиз не требуется.
Данные резервируются в `/opt/involta-guide/backups/voice-*`, secrets не печатаются.
Для последующего просмотра прогресса: operation=report и SHA работающего релиза;
для идемпотентного повторения инвентаризации operation=backfill.
Первый переход с pre-Voice приложения допускается только с проверенной приватной
резервной копией; при неудачной миграции прежний Guide восстанавливается, новые
Voice volumes сохраняются, несовместимый старый worker Voice не запускается.
После успешного включения gateway новые отзывы не откатываются восстановлением
старого дампа: отдельные ошибки backfill требуют исправления/повтора, а не потери
уже принятых сообщений.
