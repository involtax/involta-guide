# Временное публичное наполнение пустых локаций

Включено по прямому запросу владельца на период ручного тестирования production.
Кнопка **«Запарсить эти данные»** намеренно доступна **без авторизации и входа**.
Это временный механизм, который нужно убрать после тестового периода.

- Показывается на пустых страницах всех активных локаций, включая города, районы
  и курорты. Готовая подборка или любой ручной черновик скрывают кнопку.
- Нажатие запускает только текущую локацию. Тело запроса не позволяет передать
  другой город, массовый scope или собственный промпт. Используется snapshot
  текущего промпта из админки и существующий backend OpenAI с web search.
- Повторные/одновременные клики защищены PostgreSQL row lock и существующим unique
  index очереди: одно активное задание на локацию. GET и polling ничего не запускают.
- После успешной генерации сохраняются рестораны, версия страницы, полный промпт
  и модель. Первая подборка публикуется в той же транзакции. Проверки схемы,
  рейтинга, телефонов и полномочий на звезду Алекса остаются прежними.
- Если за время поиска появились ручные данные, результат не перезаписывает их.
  Обычная генерация из админки по-прежнему создаёт только черновик.
- Страница показывает ход поиска, затем обновляется и убирает кнопку. Ошибку можно
  увидеть на странице и в админке. Сетевые ошибки OpenAI не запускают автоматический
  повтор для этого публичного действия: следующий запуск снова инициирует человек.
- Ключ OpenAI остаётся только на backend. Same-origin проверка POST не является
  авторизацией: любой посетитель сайта может нажать кнопку. Это осознанный временный
  режим; существующие дневные ограничения провайдера продолжают действовать.

Новых таблиц или production-миграций нет. Источник запуска фиксируется событием
`audit.action=temporary_public_fill`, target — job UUID. Публикация помечается
`temporary_public_fill_published`; у версии страницы `source=public_fill`.
Маркер очереди не передаётся модели и не выводится в публичный ответ вместе с промптом.

## Как отключить / удалить

`TEMPORARY_PUBLIC_FILL_ENABLED=false` у web и worker отключает кнопку, публичные
маршруты и обработку оставшихся публичных заданий. По умолчанию флаг сейчас true,
чтобы механизм заработал в существующем production без редактирования env-файла.
После запроса владельца достаточно изменить default и задеплоить либо удалить:

- два `/api/locations/{slug}/fill...` маршрута и context в `web/routes/public.py`;
- блок `data-public-fill` и условный script в `web/templates/location.html`;
- `web/static/public-fill.js`;
- методы `public_fill_state` / `enqueue_public_fill` и ветку публикации публичного
  задания в `application/services/jobs.py`;
- специальный ручной retry в worker и конфигурационный флаг.

Историю версий и audit удалять не нужно. Перед удалением обработать/отменить
оставшиеся задания. Для проверки реализации используются fake AI и изолированные
схемы PostgreSQL; production-генерацию запускает сам владелец кнопкой.
