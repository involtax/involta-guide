# Числовые ID и список «Рядом»

Прямое решение владельца: у каждой локации постоянный положительный числовой ID.
UUID локаций и отдельная таблица `location_relations` удалены. UUID ресторанов,
отзывов, заданий и сессий этим изменением не затрагиваются. Публичные и
административные адреса городов по-прежнему используют slug.

## Данные

`data/location-catalog.json` содержит все 1448 исходных локаций. У каждой есть
`id` и `nearby_location_ids`, например:

```json
{"id": 490, "slug": "example-city", "nearby_location_ids": [12, 34]}
```

Это пример формата, не реальные связи. ID назначены один раз и записаны в Git;
порядок строк JSON, переименование и изменение URL не меняют идентификатор.
Не перенумеровывать справочник и не использовать удалённый ID повторно. Новую
локацию в админке нумерует identity-последовательность PostgreSQL. Перед ручным
добавлением в JSON выгрузить актуальный справочник, чтобы не занять уже выданный ID.

В PostgreSQL:

```sql
locations.id integer PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY
locations.parent_id integer REFERENCES locations(id)
locations.nearby_location_ids integer[] NOT NULL DEFAULT '{}'
```

Список направленный: Кострома → Ярославль ничего не добавляет Ярославлю или
Кинешме. Никаких общих наборов, обратных записей или транзитивного обхода.
Порядок массива определяет порядок ссылок. Сервис проверяет существование
локации, исключает повторное добавление и ссылку на себя. Импорт валидирует все
ID до записи и выполняется одной транзакцией. Физического удаления локации через
админку нет; если оно появится, операция должна очищать ID из чужих массивов.

## Git и редактирование

`guide seed` добавляет отсутствующие ID и **заменяет списки «Рядом» существующих
каталожных локаций значениями из JSON при каждом запуске**, включая пустые массивы.
Старые связи в БД не дополняют JSON. Начальный JSON сохраняет прежние 16
ненаправленных пар как 32 явно заданных направленных записи. Это только перенос
данных: обратные ссылки при дальнейших правках не генерируются.

Вступления, рестораны, отзывы, ручные правки географии и прочее содержимое
существующих локаций импорт не перезаписывает. Локации, добавленные только в БД,
не удаляются. Их ID выше зарезервированного диапазона каталога.

Админка `/guide/admin/locations/{slug}` меняет список текущего города сразу и
отдельно от «Сохранить локацию». Сохранение настроек города не очищает список.
Используется один шаблон, CSS, индекс и DOM-адаптер существующего поиска главной;
выбор в админке отправляет числовой ID, выбор на главной открывает страницу.
Форма также работает без JS: «Найти» показывает до шести результатов с кнопкой
добавления. Повторное добавление безопасно; все изменения проходят CSRF и аудит.

Изменение в админке само не коммитит Git. Чтобы сохранить его для следующих
импортов, использовать «Экспорт локаций» либо:

```sh
uv run guide export-locations > /tmp/location-catalog.json
# Проверить diff, затем заменить data/location-catalog.json и закоммитить.
```

Оба экспорта возвращают импортируемый формат `locations` + `redirects`, без
вступлений, отзывов, ресторанного содержимого, секретов и служебного состояния.

## На сайте

После отзывов, перед футером: «А еще рядом *есть*». Слово «есть» — Georgia italic.
Показываются все выбранные локации в порядке массива, без лимита и фильтра
наполненности. Если список пуст, блока нет. Имена и URL читаются из актуальных
записей локаций, отдельные URL в массиве не сохраняются. Отключённый город всё ещё
подчиняется обычным правилам доступности своей страницы; редактор отвечает за
выбор доступных направлений.

## Переход существующей установки

Миграция несовместима со старым приложением. Требуется один согласованный переход:

1. Остановить web, Guide worker, Voice API/delivery и Voice worker. Проверить
   консолидацию в одну БД, схемы Guide (обычно `public`) и Voice (обычно `voice`).
   При другом имени задать `VOICE_DATABASE_SCHEMA` и процессу Guide migration.
2. Сохранить **обе** схемы до миграции: Guide и Voice. Скрипт релиза сначала
   консолидирует старую отдельную БД Voice при необходимости, затем сохраняет
   её копию, и лишь после этого запускает общую миграцию ID. Аудиотом сохраняется.
3. `uv run alembic upgrade head` (`location_ids` после `audience_stats`): сопоставить
   UUID с ID JSON по прежнему детерминированному UUID или slug; дополнительным
   локациям выдать ID выше диапазона JSON. Коллизия или неизвестная ссылка
   прерывает всю транзакцию. Временная карта UUID → ID удаляется при commit.
4. В одной транзакции меняются PK, parent_id и все location_id обеих схем,
   восстанавливаются FK и триггеры. Сохраняются содержимое, эпохи, номера логов
   и отзывов. Структурированные контексты, очередь Voice/inbox/outbox и ключи
   идемпотентности переходят на числовые ID. UUID других сущностей, имена файлов
   аудио и исходные текстовые запросы/ответы провайдеров остаются прежними.
5. `uv run guide seed`: применить Git-каталог и списки «Рядом».
6. `uv run voice migrate`: версия 10 подтверждает числовой контракт. Для пустой
   новой Voice-схемы она сама меняет типы; заполненную UUID-схему без общей
   миграции принимать отказывается. Запустить сервисы одной версии.
7. При откате остановить всех писателей, восстановить **обе** копии и предыдущий
   образ. Откат только образа или одной схемы недопустим.

Эти команды описывают будущий переход, не подтверждают production-миграцию.

## Ручная проверка сборки PR

- `/guide/admin/locations/kostroma`: добавить Ярославль через знакомый поиск;
  повторно выбрать его — дубля нет. Убрать — исчезает только у Костромы.
- `/guide/admin/locations/kineshma`: список Кинешмы не меняется.
- Сохранить настройки Костромы: список не пропадает. Обновить страницу и
  перейти в другой город через sidebar: подсказки поиска продолжают работать.
- `/guide/kostroma`: после отзывов появляется новый блок с выбранными ссылками.
  `/guide/kineshma` не получает ссылок Костромы. На 360/390/768 px нет переполнения.
- `/guide/admin/locations/export`: числовые ID и массивы, формат пригоден для
  Git-каталога. После повторного seed Git-списки заменяют локальные изменения.
- На заполненном городе: проверить вступление, рестораны, старые логи и отзывы;
  отправить тестовую запись и дождаться её обычного появления в ленте.
