# Панорамы локаций

Утверждён вариант 05 «Панорама». Первая иллюстрация — Плёс.
Пасхалка и абстрактные продолжения в эту реализацию не входят.

## Добавить картинку без изменения кода

1. Взять **канонический slug** из адреса локации: `/guide/ples` → `ples`.
   Для московского района использовать slug именно района, а не `moskva`.
2. Подготовить **PNG RGBA, 2172 × 724 px, строго 3:1**. Прозрачный фон,
   синий рисунок с мягким растворением в белом, основной объект справа.
   Не обрезать прозрачные поля исходника: они участвуют в композиции.
3. Положить файл в `src/involta_guide/web/static/panoramas/<slug>.png`.
4. Закоммитить файл, пройти CI и выпустить обычный релиз.

Например, добавление `ivanovo.png` автоматически подключает иллюстрацию
на `/guide/ivanovo`. БД, шаблон, JS и реестр картинок менять не требуется.
Файл определяется сервером по slug при каждом рендеринге HTML; отрицательного
кеша нет. Удаление файла возвращает обычную страницу. Нет картинки — нет
пустого блока, запросов отсутствующего PNG или кода анимации на странице.
Добавление в Git само по себе не обновляет production: нужен релиз.

PNG хранится непосредственно в Git, без Git LFS, CDN и внешнего хранилища.
Текущий `ples.png` — оригинал из утверждённого макета, **2 236 505 байт**;
публичный адрес после релиза: `/guide/assets/panoramas/ples.png`.
Контракт размеров всех PNG проверяется тестом. Рекомендуется оптимизация
без потери прозрачности; изменение размера требует нового решения по дизайну.

## Геометрия и позиционирование

| Параметр | Значение |
| --- | --- |
| Исходный холст | **2172 × 724 px**, 3:1 |
| HTML `width` / `height` | `2172` / `724`, резервируют пропорцию до загрузки |
| Широкий экран, **651 CSS px и больше** | Ширина изображения = ширина viewport без вертикального scrollbar; высота = ширина / 3 |
| Мобильный экран, **650 CSS px и меньше** | **1000 × 333⅓ CSS px**, viewport вырезает видимую часть |
| Ширина блока | Весь viewport, без боковых отступов; текст сохраняет обычные поля страницы |
| Горизонтальный вынос из контейнера | `margin-left: (100% - viewportWidth) / 2` |
| Вертикальное наложение | `margin-top: -clamp(120px, 20vw, 280px)` после блока вступления |
| Примеры наложения | 390 px → **−120 px**; 768 px → **−153.6 px**; 1440 px → **−280 px** |
| Положение текста | Заголовок и вступление выше рисунка по z-index; белая тень у вступления |
| Прозрачность изображения | **0.9** |

На десктопе виден весь исходник, включая оба естественных края; автодвижения нет.
На мобильном первоначальный `scrollLeft = 1000 − viewportWidth − 120`:
при ширине 390 px это **490 px**, видимый участок исходника —
примерно **x = 1064.3…1911.4 px**. До правого края изображения остаётся
**120 CSS px = 260.64 px исходника**: основной объект справа виден,
а закругление края не попадает в начальный кадр.

После загрузки движется видимое окно: `scrollLeft` сначала уменьшается,
то есть пользователь смотрит всё левее по рисунку. Скорость **14 CSS px/с**.
Автоматический диапазон: `120…(1000 − viewportWidth − 120)`;
у узкого диапазона обе границы сходятся посередине. В пределах **55 px**
от разворота движение замедляется до **18%** скорости и меняет направление.
Нет скачка из конца в начало и дублирования рисунка.

## Ручная прокрутка и доступность

- Полный ручной диапазон: **0…(1000 − viewportWidth)**. До обоих настоящих
  краёв можно дойти пальцем, перетаскиванием мыши, горизонтальным колесом,
  Shift+колесом, стрелками, Home и End. Полоса прокрутки скрыта.
- Оттягивание за край даёт затухающее смещение до **66 px**;
  упругий возврат длится **440 ms**. После свайпа есть инерция.
- После горизонтального взаимодействия автодвижение возобновляется через
  **1800 ms**, плавно из текущего положения. Вертикальная прокрутка,
  фокус и hover не останавливают его; вертикальный жест прокручивает страницу.
- Кнопок паузы и воспроизведения нет: движение автоматическое.
  При `prefers-reduced-motion: reduce` автоматическое движение, инерция
  и упругий возврат отключены, ручная прокрутка работает.
- В скрытой вкладке анимация не работает; при возвращении не догоняет время.
  На широком экране кадры анимации не запрашиваются.
- Без JavaScript картинка остаётся видна, доступна нативная горизонтальная
  прокрутка. Автоматики и упругого эффекта нет, начальный кадр — левый.

Только на страницах с панорамой убраны «Стоит зайти» и две верхние линии
перед первым рестораном. Разделители между ресторанами сохранены.
Вступление берётся целиком из БД; текст не обрезается автоматически.

## Проверка

`tests/unit/test_panoramas.py` проверяет размеры файлов, соответствие имени
и автоматическое обнаружение нового изображения, а также безопасные пути.
`tests/e2e/test_location_panorama.py` проверяет настоящую страницу через
PostgreSQL + HTTP + Chromium: геометрию, мобильное движение и жесты,
достижение обоих краёв, упругий возврат, отсутствие кнопок управления, reduced motion,
десктоп и страницы без картинки. Платных AI-вызовов нет.

Скриншоты реализации с тестовыми текстами и ресторанами:
