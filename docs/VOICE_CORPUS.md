# Реальные отзывы: выгрузка и локальная проверка

В бете владелец разрешил внешнее чтение логов и аудио неудалённых отзывов.
Это read-only представления существующих данных, без новых сущностей/миграций,
переобработки, отправок OpenAI или административных cookies.

| Представление | URL относительно BASE_PATH |
| --- | --- |
| Индекс всех неудалённых отзывов | `/logs/reviews.json?after=0&limit=100` |
| Полный безопасный JSON-лог | `/logs/reviews/{slug}/{number}.json` |
| HTML-лог | `/logs/reviews/{slug}/{number}` |
| Исходное аудио | `/logs/reviews/{slug}/{number}/audio` |
| Проигрываемый WebM | тот же путь с `?playback=true` |

Индекс включает publication_status0/1, reference, номер/город, время, текст,
длительность и адреса. next_after=null означает конец. limit1..200, порядок —
монотонный номер. Удалённые записи исключены, новые появляются при следующей
выгрузке. JSON-лог содержит Guide detail/events/actions, Voice status/stages/raw,
сравнение ASR и состояние доставки. Cookie, IP, visitor/user-agent, credentials
и сырые персональные metadata исключаются тем же фильтром, что в HTML.

При ошибке Voice JSON-лог сохраняет Guide-часть и unavailable; выгрузка сообщает
об отсутствующем аудио, не выдавая неполный корпус за полный. Во время удаления
параллельно с выгрузкой возможен404; повторная выгрузка обновляет состав.

```sh
python tools/download-voice-corpus.py \
  --base-url https://involta.ru/guide/ --output var/voice-corpus
```

Только GET. Скрипт скачивает JSON и оригинальные файлы, проверяет audio SHA256
против Voice, повторно использует подтверждённые локальные аудио, обновляет логи.
Состав задаёт index.json, а не сканирование всех файлов. Старые файлы удалённых
отзывов удаляются только если были созданы этим инструментом; чужие файлы не
трогаются. При временной ошибке сохранившегося отзыва старое аудио не удаляется.
Каталог приватный, файлы0600, var/ исключён из Git. Не коммитить записи и их полные
расшифровки, не публиковать корпус в PR/artifacts. Файлы доступны агенту локально.

## Проверка ASR

Нужен `uv sync --frozen --extra voice-local`, подготовленные GigaAM/Sherpa и VAD
(`voice prepare-model`, VOICE_ASR_MODELS_DIR). Исследование запускается на файлах
из свежего index.json, не на удалённых отзывах и не на синтетической речи.
Сохранять exact request/dictionary, audio/PCM SHA256, VAD intervals, elapsed time,
raw text и результат форматирования. Сравнивать параметры на одном файле, не
производить автоматическое массовое изменение публикаций.

Конфигурация текущего кода — единственный проход2.5/16. Сохранённые production-запросы имеют собственные зафиксированные параметры. Локальные сравнения
могут отключать/ослаблять словарь; это не включает дополнительные production-модели.
При анализе повторов проверять сырой ASR до нормализации. Не удалять повторы
механически: они могут быть произнесены человеком. Словарь блюд и удаление
слов-паразитов сначала проверять на реальных записях; raw хранится неизменным.

## Плеер

MediaRecorder WebM может не иметь Duration/SeekHead; браузер видит Infinity.
Воспроизведение получает временное seekable-представление: PyAV перепаковывает
те же Opus/Vorbis packets с duration/index без перекодирования, детерминированно,
в памяти. Оно не сохраняется как второй оригинал. Range/If-Range и Content-Range,
Content-Length, ETag передаются через Guide. Оригинал для ASR/скачивания неизменен.
Нативное меню скрыто controlslist, лог-ссылок в админке нет.

## Переход в альфу — обязательное действие

Владелец определяет момент перехода. Закрыть анонимный доступ одновременно к
HTML/JSON-логам, индексу и всем файлам, включая playback=true. Уже сейчас
PUBLIC_FILL_LOGS_ENABLED=false закрывает эти пути без входа администратора.
При переходе предоставить агенту простой секретный токен по общей проверке
доступа; хранить его в окружении/менеджере секретов, не в Git, URL или browser bundle.
Не отрезать агенту диагностику и не оставлять публичным обход через файлы.

Пример локального сравнения (score0 отключает подсказки):

```sh
uv run --extra voice-local python tools/replay-voice-corpus.py \
  --corpus var/voice-corpus --models-dir /path/to/prepared-models \
  --reviews 15 37 38 --scores 0 3 4.5 5.5 --search 8 \
  --output var/voice-corpus/comparison.json
```

По умолчанию используются названия из сохранённого контекста отзыва. Для текущего
контекста города — `--catalogue latest`, для эксперимента с блюдами —
`--extra-words рамен креветки`, для ещё не созданных ресторанов —
`--extra-restaurants Алхимист Терраса Горы` (только для выбранного города).
Полный request и дополнительные слова фиксируются
в результате; нельзя выдавать подсказанный ожидаемый ответ за независимую оценку.
Скрипт не обращается к PostgreSQL/OpenAI и не изменяет production-отзывы.
Для сравнения независимой нарезки VAD и нового контекста хвоста использовать
`--no-tail-context`: он убирает из локального запроса только vad_tail_context,
сохраняя веса/словарь/модель. Без флага применяется текущая версия. Оба варианта
сохраняют исходные vad_segments и реально распознанные segments в JSON-результат.
`raw_text` сохраняет ASR; `names_restored_text` — только словарное написание;
`formatted_text` применяет текущую функцию очистки/соединения из production-кода.
Это локальный просмотр нового форматирования, не изменение старых run snapshot.

## Форматирование новых отзывов

После словарного восстановления имён применяется `hesitations-restaurant-fragments-v1`:
отдельные протяжные «э-э», «эээ», «а-а» удаляются вместе с зависимой запятой;
сохраняются паузы-многоточия и восстанавливается начало предложения. Обычные
«а», «ну», «эм», слова и повторы не вырезаются. Это консервативная правка для
читаемости, не определение намерения говорящего по аудио.

«Также/Ещё ресторан. Название» соединяется только если название точно совпадает
с рестораном из frozen recognition_dictionary. Город исключается из этого
правила. Законченные предложения, неизвестные названия и согласование слов
сохраняются. Например: «Мне понравился ресторан. Горы видны из окна» не меняется.

Версия записана в run snapshot `review_text_format` при приёме; уже принятые
задания без неё форматируются по старым правилам. Сохранённый raw ASR и оригинал
аудио не изменяются. Если после очистки осталось только междометие/пунктуация,
новый отзыв завершается обычной ошибкой распознавания, без публикации пустого
текста и без нового вызова модели; raw ответ остаётся в журнале.

## Повторное распознавание на сервере

Кнопка «Перераспознать» в админской карточке запускает новый run на **том же**
аудио с текущими настройками и актуальным каталогом. Словарь старого run не
изменяется. Исходный текст остаётся на сайте до успеха, старые результаты — в
истории. Удалять/записывать отзыв заново не требуется. Контракт и гарантии:
[VOICE_API.md](VOICE_API.md#административное-перераспознавание).
