# Предложение: поиск локаций на главной

**Статус: корпус «Фарфор» (04) выбран владельцем; выбираем кнопку.**
Продуктовые шаблоны, сервер, БД и production не изменены. Прототип на тестовых
данных: выбор заполняет поле, отправка эмулируется без реального перехода.

Открыть [index.html](index.html). Скрипты и CSS локальные; сборка и CDN не нужны.
Текущий выбор — [десять кнопок на «Фарфоре»](buttons.html).
Первое сравнение корпусов сохранено в [галерее оформления](gallery.html).
«На главной» показывает вариант в контексте страницы. `index.html?button=01`
выбирает кнопку; корпус в этом режиме всегда «Фарфор». Без параметров главная
также использует выбранный корпус 04, со спокойной исходной кнопкой.

## Выбранный корпус и новый акцент

Владелец выбрал «Фарфор» именно за его лёгкую, компактную нейтральную тень:
в покое `0 1px 5px rgb(32 33 36 / 4%)`, при раскрытии
`0 3px 14px rgb(32 33 36 / 7%)`. Тень близко к форме, без широкого тёмного ореола.
Эти значения и единая оболочка строки/подсказок сохраняются во всех десяти
кнопочных вариантах. Новых цветных теней у кнопки нет.

Кнопка — главный цветовой акцент, поле и подсказки остаются спокойными.
Предложены сине-голубой прямоугольник с белым «Найти», синяя капсула, синий
правый край строки, индиго, бирюзовый овал, коралл, оранжевый овал, жёлтая
компактная кнопка, графитовая капсула и синий круг со стрелкой.
Варианты 01–09 сохраняют надпись «Найти» на телефоне; 10 сравнивает вариант
с одной стрелкой. Цвет, форма и номер кнопки ещё не выбраны.
Все десять вариантов проверены на 1440 и 390 px: выбор подсказок клавиатурой
и кликом/touch, отправка кнопкой, видимость подписи 01–09 на телефоне,
отсутствие горизонтального переполнения и сохранение теней корпуса.
Контраст текста на фонах кнопок — от 4,56:1; у оранжевой и жёлтой текст тёмный.
Для просмотра через HTTP из корня репозитория:

```sh
python -m http.server 8080
# /docs/design/location-search/index.html
```

## Выбор компонента

**autoComplete.js 10.2.10**, лицензия Apache-2.0, фиксированная версия в `vendor/`.
Проверены исходники выбранного релиза и конфигурация, а не только рекламное описание.
Скачанный min.js: 9 367 байт, gzip: 3 789 байт. Для сравнения, standalone-сборка
GOV.UK Accessible Autocomplete 3.0.2 — 54 971 / 18 965 байт. Это измерение файлов,
не обещание фактического размера HTTP-ответа без настройки gzip на сервере.
GOV.UK также сообщает об ограниченном объёме поддержки компонента.

Компонент небольшой, без runtime-зависимостей, работает с существующим полем,
позволяет полностью задать стили/вывод строк и управление. Не подключаем его
стандартную тему. Небольшой адаптер Guide управляет сетью; библиотека — списком,
ARIA и выбором. У штатного поведения есть ограничения: Escape очищает поле,
а асинхронные ответы сами по себе не защищены от гонок. Поэтому их нельзя просто
подключить примером `data.src = fetch`. Escape переопределяется; запросами
управляет адаптер с поколением ввода и AbortController.

Источники:
- [Фиксированный релиз](https://github.com/TarekRaafat/autoComplete.js/releases/tag/v10.2.10).
- [Конфигурация](https://github.com/TarekRaafat/autoComplete.js/blob/v10.2.10/docs/configuration.md).
- [Поддержка GOV.UK](https://github.com/alphagov/accessible-autocomplete#support).

## Главная и поведение

Сразу под существующим H1 — широкое подписанное поле «Куда отправимся?».
Прежний поиск из раздела городов переносится сюда, второго поля нет.
Объяснение гида становится небольшим текстом под поиском. Ниже остаются готовые
подборки: самостоятельный способ навигации и полезное содержимое без ввода.

По замечаниям Алекса убраны жёсткая рамка, прямые углы и разлиновка подсказок.
Раскрытый поиск — **одна общая форма**: строка и выдача лежат внутри одной
`.search-surface`, с единым фоном, внешним контуром и скруглением. Подсказки
продолжают поле без зазора, собственной рамки или отдельной тени. Внутренняя
тонкая линия под вводом не доходит до краёв. Отдельная плавающая панель отменена.

В первом сравнении были предложены десять корпусов; из них выбран 04 «Фарфор»:

| 01 | Белый классический | Белый фон, тонкая серая граница, мягкая тень |
| 02 | Только тень | Белый фон без обводки, одна внешняя тень |
| 03 | Светло-серый | Серый корпус, белая выбранная строка |

| 10 | Тёмная точка | Белый корпус, небольшая круглая тёмная кнопка |

Галерея использует тот же интерактивный компонент через iframe: три одинаковые
подсказки в каждом примере, чтобы сравнивать оформление. Полная главная показывает
до шести. Все варианты заданы CSS-переменными, библиотека и поведение общие;
это набор макетов для выбора, не десять реализаций будущего продукта.

Ширина в главной ограничена 860 px, гарнитуры — Arial/Georgia. Подсказка — две
строки: название и тип/регион; для одноимённых мест также родитель. Совпадение
выделяется начертанием, без цвета. Общая оболочка растёт поверх нижнего содержимого,
сохраняя положение поля и страницы при раскрытии/закрытии.

- От двух символов, пауза 180 мс, максимум шесть результатов.
- Пустое поле не запрашивает сервер, автофокус не открывает клавиатуру телефона.
- Стрелки выбирают, Enter по выбранному пункту открывает канонический URL.
  Enter без выбора и кнопка «Найти» отправляют обычный GET поиска. Первый пункт
  не выбирается автоматически. Tab сохраняет обычный переход фокуса.
- Escape закрывает список и сохраняет запрос. Крестик очищает и возвращает фокус.
- «Все результаты» открывает тот же GET-поиск без подсчёта общего числа на каждый ввод.
- На телефоне строки минимум 48 px, список ограничен доступной высотой и
  прокручивается внутри. При открытой клавиатуре поле поднимается в видимую
  область; это надо проверить на реальных iOS/Android при интеграции.
- Отсутствие совпадений, загрузка и сбой — разные состояния. Загрузка объявляется
  после небольшой задержки, без мигания на быстрых ответах. При сбое обычная форма
  остаётся работоспособной. Прототип содержит пустую выдачу и `?state=error`.
- Имена строятся DOM textContent/текстовыми узлами; HTML из каталога не исполняется.

Прототип проверен в Chromium на 1440 и 390 px: выбор стрелками/Enter и кликом/touch,
Enter без выбора, Escape, очистка, е/ё, различение одноимённых мест, пустая выдача
и сбой, отсутствие горизонтального переполнения и JS-ошибок.
Это не проверка сетевых гонок или реальной экранной клавиатуры.

## Backend: схема и контракт

Сейчас: GET главной → `search_locations` → COUNT + SELECT l.* + пагинация.
Предлагается: ввод → GET `/guide/api/locations/suggest?q=нов` → отдельный компактный
SELECT с LIMIT 6, без COUNT, общего числа страниц и полей содержимого/админки.

```json
{
  "items": [
    {
      "name": "Великий Новгород",
      "context": "Город · Новгородская область",
      "url": "/guide/velikiy-novgorod"
    }
  ]
}
```

`locations` остаётся источником истины: name, region, aliases, slug, kind, parent_id,
active, listed/правило PUBLIC и факт наполнения. Новых таблиц/поискового сервиса нет.
Для ошибок ввода предлагается штатное расширение PostgreSQL `pg_trgm` и один
GIN-индекс выражения `translate(lower(name),'ё','е')`. Это миграция индекса,
без второго каталога и хранимого «поискового текста». Алиасы читаются из текущего
поля, без отдельной синхронизации. Порядок/стоимость запросов проверяются EXPLAIN
на фактическом каталоге; ~1 448 записей в исходном каталоге не требуют внешнего движка.

Правила совпадений общие для подсказок и обычного GET-поиска:

1. Нормализация регистра, е/ё, пробелов и разделителей. Несколько слов могут идти
   в разном порядке. Ищем название, существующие алиасы, slug и регион/родителя.
2. Точное название → точный алиас → начало слова в названии/алиасе → вхождение
   в название → контекст региона. На равной релевантности выше готовые подборки,
   затем текущий приоритет и устойчивый порядок name/id. Готовый чужой город
   не вытесняет точное совпадение с нужным.
3. Если нормального совпадения нет: проверка ошибочной английской раскладки
   (`cjxb` → «сочи»), затем для запросов от четырёх символов ограниченный поиск
   по похожести `pg_trgm` с порогом. Не превращаем любой бессмысленный запрос в
   ближайший город и не исправляем ввод молча. Дополнительный SQL выполняется
   только в этом случае. Полная транслитерация не заявляется: Latin slug/алиас
   поддерживаются, произвольные варианты написания требуют реальных алиасов.

Ищем все публично доступные типы локаций, как текущий поиск. Скрытые/отключённые
страницы исключаются тем же PUBLIC-правилом, что основная навигация. У одинаковых
названий сохраняются разные URL и уточняющий контекст. Если несколько алиасов
совпали, локация появляется один раз. Новые алиасы вроде «Питер» — изменение
каталога, не магическое свойство виджета; сейчас такого алиаса в исходных данных нет.

API ограничивает q 100 символами, короткий/пустой запрос возвращает items: [].
Параметризованный SQL, экранирование `%`/`_`, фиксированный сервером LIMIT,
ограниченное время SQL и короткий публичный HTTP-кеш 30 секунд. Fetch с
`credentials: 'omit'` не передаёт cookies; API их не выдаёт. Не добавляются журнал
поиска в приложении, увеличение хитов, AI, геокодирование или запуск наполнения
при вводе. Единственное действие выбора — переход на существующую страницу.

Сервер владеет фильтрацией/ранжированием; клиент не фильтрует готовую выдачу второй
раз и не скачивает весь каталог. Адаптер отменяет старый fetch на каждом изменении,
сразу скрывает прежние результаты и принимает ответ только для актуального
поколения ввода/фокуса. Запросы игнорируют промежуточную IME-композицию. Потеря
фокуса/Escape/очистка также не позволяют позднему ответу снова открыть список.
HTTP-кеш сокращает повторы при Backspace; отдельные Redis и браузерный кеш-словарь
не нужны. Страница работает обычной формой при отсутствии/ошибке JS.

Документация поиска с опечатками:
[PostgreSQL pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html).

## Приёмка после согласования

Минимальные проверки по поведению: релевантность и приватность выдачи; короткие
и опасные строки; е/ё/алиасы/одноимённые места/раскладка/порог опечаток; обратный
порядок HTTP-ответов, закрытие и IME; клавиатура, клик и touch; отключённый JS и
ошибка API; мобильный viewport с клавиатурой; отсутствие запуска платной работы.
Один проход по frontend-сценарию и несколько тестов серверных границ, без теста
на каждую CSS-строку и без повторного полного набора ради макета.
