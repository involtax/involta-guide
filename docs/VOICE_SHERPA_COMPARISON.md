# GigaAM/Sherpa: один основной профиль

Для каждой новой записи выполняется один проход: `sherpa_hotwords_strong`,
сила подсказок **2.5**, поиск **16**, город и все рестораны его каталога.
Onnx-asr, Parakeet, контрольные и другие сравнительные профили не создаются.
Уже принятые задания сохраняют свои параметры/источник; старые результаты и аудио
не удаляются. Новый эксперимент можно подключить через существующий список
активных профилей, без отдельного сервиса или очереди. Сейчас в нём одна запись.

## Словарь, словоформы и публикация

Общая подсказка для всех городов — «Алекс Концов» (также строчное написание).
Она фиксируется в ASR-запросе и отдельно в `common_recognition_names` snapshot.
Точное написание полного имени восстанавливается после ASR; это не ресторанное
название и не основание соединять фрагмент «Также ресторан. …». Старые запросы
не дополняются автоматически.

ASR-словарь остаётся прежним: полное имя города и все названия ресторанов,
каноническое и строчное написание. Словоформы не меняют силу подсказок или ASR-веса.

После ASR нормализация восстанавливает каталоговое написание, сохраняя падеж:
«в иванове» → «в Иванове», «в плёсе/плесе» → «в Плёсе», «в орле» → «в Орле».
Для известных слов pymorphy3 2.0.6 / pymorphy3-dicts-ru 2.4.417150.4580142
формируют словоформы. Выбираются именные разборы в именительном падеже, для
географических названий предпочтителен Geox. У составных городов учитывается
согласование и неодушевлённый винительный падеж. Fixd остаются неизменными.
Неизвестные и смешанные брендовые написания не склоняются по догадке.

Сопоставляются целые имена, длинные раньше коротких. Е/ё разрешены для поиска;
вывод сохраняет написание словаря. Коллизии автоматически полученных форм
пропускаются; точное каталоговое имя имеет приоритет. «ивановский», «плёсовый»,
«москвич», «плюс» не становятся именами из-за похожего начала.

runs.snapshot фиксирует `primary_variant=sherpa_hotwords_strong`,
`name_normalization=catalogue-inflections-v1` и `name_forms` при приёме аудио.
Worker использует сохранённую таблицу, а не пересчитывает её по изменённому каталогу.
Старые runs без name_forms сохраняют прежнее точное сопоставление.

Сырые provider_calls/asr_candidates неизменны. Форматированный текст сохраняется
в submissions/runs и доставляется в Guide существующим событием gigaam_ready.
В админке одна строка новых отзывов: «До» и «После», настройки и точный ASR-словарь.
Чтение старого отзыва не запускает ASR и не применяет к нему новые правила.

## Родной SentencePiece

Прежний сгенерированный bpe.vocab содержал нулевые оценки всех частей слов.
Sherpa могла разбивать названия на неподходящие короткие части, ослабляя подсказки.
Теперь используется исходный токенизатор GigaAM с сохранёнными оценками частей;
все 1024 ID проверяются на соответствие закреплённому ONNX-экспорту.

- encoding: `gigaam-sentencepiece-native-v2`;
- tokenizer SHA256: `828c12c991019eef952a960661f25a92d6ad279591e2ea466b4aeddf1d20a18a`;
- vocabulary SHA256: `af72e53d851552fca7510fd1aa8ca7db340407ee1c57bd34c4bafaec1a79529c`;
- файл: `bpe.gigaam-native-v2.vocab`, создаётся prepare-model атомарно.

Происхождение и MIT-лицензия — в `src/involta_voice/assets/`. Токенизатор включён
в образ; сверка SHA и ID выполняется до готовности моделей. Worker проверяет hash
перед inference и явно ошибается при отсутствии/повреждении файла, без fallback.

## Исполнение и сохранение истории

Прежний voice-worker выполняет один новый проход. Используются
modified_beam_search и length_reward=0. PyAV mono 16 kHz, Silero VAD, максимум участка
20 s, минимум паузы 500 ms сохраняются. Веса, quantization и ревизия runtime не меняются.
Sherpa закреплена на commit `3898de1380029e96a3b0a3df9e21e3f5ee5eb7fb`.

Новых миграций нет: Voice schema 9. Источник публикации заморожен в snapshot;
для старых запросов без этого поля остаётся onnx-asr. Уже принятые задания используют
свои настройки и encoding. Подготовка не перезаписывает старый bpe.vocab.
Старые отзывы не пересчитываются, аудио/сырые результаты/логи не удаляются.
Идемпотентность, heartbeat, lease/epoch fencing и reuse сохранённого raw сохраняются.
Ошибка сравнительного профиля не меняет публикацию основного.

## Проверки и выпуск

### Контекст короткого концевого участка

Новые запросы фиксируют `vad_tail_context=short-tail-context-v1`. Если последний
участок VAD короче400мс, пауза до него не больше3с, а объединённый интервал
укладывается в20с (и max_speech_duration_s запроса), он подаётся в ASR вместе с
предыдущим участком и исходной паузой. Звук не отбрасывается, текст не фильтруется
по словам. Короткие одиночные и внутренние реплики остаются самостоятельными.

Это исправляет воспроизведённое лишнее окончание отзыва42: отдельный участок
длиной316мс давал ложное слово даже без словаря. Увеличение поиска и снижение
весов его не устраняли; контекст предыдущей речи устранил. Профиль2.5/16,
модель, VAD-веса и исходный PCM не меняются. Цена — обработка дополнительной
паузы до3с, только при срабатывании правила.

В raw ответе `vad_segments` сохраняет исходные интервалы VAD, `segments` — реально
распознанные интервалы и текст, `vad_tail_context_applied` — факт объединения.
Запросы без версии исполняются по прежней нарезке; неизвестная версия вызывает
явную ошибку. Семантику v1 не менять при будущей настройке границ: нужна новая
версия с сохранением исполнения принятых v1-заданий.

Локальная проверка на12 сохранённых оригиналах: лишнее окончание42 устранено,
остальные11 raw/форматированных текстов совпали побайтно с исходной обработкой.
Это ограниченный корпус, не общая оценка WER/CER. Аудио/полные расшифровки не в Git.

Исторически на предоставленной владельцем записи основной 5/8 и сильный/широкий варианты
распознали названия в фразе «Плёс, плюс, плёс равно плёс в квадрате»; после обработки
публикуется «Плёс, плюс, Плёс равно Плёс в квадрате». Это один пример, а не оценка
точности по другим голосам и городам. Исходная личная запись в репозиторий не включена.

Проверки покрывают реальный SentencePiece и его hash/ID, подготовку без изменения
старого словаря, источник публикации, регистр, ошибки/lease, старые задания и админку
390/1440 px, словоформы Иваново/Плёс/Ярославль/Москва/Орёл/Сочи и составных городов. Скриншоты текущей карточки — `design/voice-sherpa-comparison/admin-*.png`.
Исторические native-results.json и native-seven-profiles.json относятся к прежним
профилям и не являются проверкой текущей точности.

Полный выпуск: build/test образа → backup и остановка writers → migrate (9) →
prepare-model (GigaAM/Sherpa + VAD, новый versioned vocabulary) → все компоненты
одного SHA → readiness/worker health/HTTPS. См. [VOICE_RUNTIME.md](VOICE_RUNTIME.md).

## Исправление словарного усиления, 5 ноября 2026

`hotwords_score` начисляется за каждый токен, а не за название целиком.
Сила5.5 приводила к повторяющимся вставкам названий и потере настоящих фраз.
Локально подобрана сила2.5 и поиск16; в словарь добавлены падежные формы города. Модель и токенизация сохранены.
Внутренний ID `sherpa_hotwords_strong` сохранён для истории; фактические значения
видны в request/snapshot каждого запуска. Старые запросы не переписываются.
Хронология и контрольные результаты: [разбор регрессии](ASR_REGRESSION_2026-11-05.md).
