# Бета: три варианта GigaAM

По решению владельца Parakeet исключён. Для каждого нового отзыва сравниваются:

| Исполнитель | variant | Словарь |
| --- | --- | --- |
| onnx-asr | onnx | нет |
| Sherpa | sherpa_plain | нет |
| Sherpa | sherpa_hotwords | населённый пункт и все рестораны его каталога |

Публичным текстом остаётся только исходный GigaAM/onnx-asr. Ошибка Sherpa не мешает
публикации primary; успешная Sherpa не заменяет ошибочный primary. Модерация,
эталонные тексты, оценки ASR и редактор словаря не добавляются.

## Словарь и исполнение

Guide формирует `SubmissionMetadata.location.recognition_dictionary` на сервере
из названия населённого пункта и всех названий его ресторанов, без лимита 200 и
без ограничения публичным топом. Например, для Плёса подсказки включают «Плёс».
Пробелы нормализуются, дубликаты удаляются, список сортируется. Иностранные названия
сохраняются как в каталоге; склонения и автоматические алиасы пока не добавляются.

Список и параметры фиксируются в runs.snapshot при приёме аудио. Последующее
редактирование каталога их не меняет. В существующей карточке админки один плеер,
три строки GigaAM и фактический словарь у каждого результата. Старые отзывы
показывают имеющиеся варианты GigaAM. Чтение не запускает inference.

Работает прежний voice-worker: три задания последовательно, primary с приоритетом,
одна тяжёлая модель в памяти. Sherpa использует одинаковый modified_beam_search,
max_active_paths=4, hotwords_score=1.5, length_reward=0 в обоих режимах. Отличаются
только variant и dictionary. PyAV mono 16 kHz, Silero VAD, максимум участка 20 s и
минимум паузы 500 ms сохраняются. Все параметры и ревизии записываются в request.

Подсказки передаются UTF-8 файлом; это сохраняет '/' в названиях. BPE-представление
строится из tokens.txt алгоритмом tokens-longest-match-v1. Управляющий префикс ':'
в названии даёт наблюдаемую ошибку сравнения, не меняя веса скрытно.

## Сохранение данных и переход

Новые задания Parakeet не создаются; модели Parakeet не скачиваются и не загружаются.
При получении работы воркер помечает ожидающие или прерванные задания Parakeet
завершёнными с ошибкой «Parakeet удалён из эксперимента». Их requests/raw-ответы,
кандидаты, исходные аудио и события не удаляются. Исторические результаты доступны
в подробном логе, но исключены из карточки сравнения. Аудио заново не обрабатываются.
Старая структура БД остаётся для сохранности истории: schema 8, ключ результата
(submission,run,engine,variant). Новая миграция не нужна.

Идемпотентность, lease/epoch fencing, ограниченное восстановление локальных заданий
и повторное применение сохранённого raw-ответа без нового inference сохраняются.

## Сборка и запуск

Sherpa закреплена на commit 3898de1380029e96a3b0a3df9e21e3f5ee5eb7fb с исправлением
TDT #4084. uv собирает CPU-библиотеку; нужны development headers Python 3.13,
C++ compiler и git. Docker собирает её в builder, VPS получает готовый образ.
Runtime проверяет PEP 610 commit: upstream git_sha1 содержит старое значение.

`voice prepare-model` готовит только оригинальный GigaAM, его Sherpa-экспорт и VAD.
Существующие файлы Parakeet в model volume автоматически не удаляются. Порядок
полного выпуска и резервного копирования: [VOICE_RUNTIME.md](VOICE_RUNTIME.md).
В production Compose включён полный профиль трёх вариантов.

Исторические замеры шести вариантов и исходные результаты сохранены в
[native-results.json](design/voice-sherpa-comparison/native-results.json).
Они получены на публичном русском аудиопримере 11.29 s и повторе 45.16 s,
а не на записях владельца. Старые макеты в этой папке отражают прежние шесть строк;
актуальные скриншоты трёх строк прикладываются в PR. Улучшение точности на живых
ресторанных отзывах определяем сравнением результатов, не синтетической речью.
