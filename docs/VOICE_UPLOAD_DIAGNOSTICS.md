# Проверка тайм-аута загрузки, 04.11.2026

## Подтверждённые факты

На странице Иванова браузер дважды получил HTML `504 Gateway Time-out` от
`nginx/1.28.3` при отправке одной записи: 20 280 мс, 326 669 байт,
`audio/webm;codecs=opus`. Идентификаторы HTTP-попыток:

- `524488ee-afda-4dbc-8aa8-e6fcc2438ddb`: начало 07:34:35 UTC, ожидание 60 623 мс.
- `ebccea96-a7af-492e-9e76-0ea7b36e3f91`: начало 07:38:04 UTC, ожидание 60 364 мс.

Для обеих попыток Guide сохранил событие `received`, затем отдельным запросом
сохранил диагностический отчёт браузера. Событий `response`/`interrupted` нет.
Аудио этой отправки не обнаружено ни в `submissions`, ни среди файлов Voice.
Браузер сообщил об успешном локальном сохранении; фактическое содержимое этой
локальной копии агенту недоступно и не проверялось.

Предыдущая запись на 15,50 с / 250 355 байт была принята за 228 мс по серверному
журналу. Это **не доказывает** порог по размеру или длительности.

Исходная ревизия Guide — `67c1db6`. Пока шло исследование, другой агент выполнил
свой деплой `dff170e`; текущий health подтверждён отдельно. Снимок соединений и БД
получен после этого перезапуска Guide: текущих блокировок нет, но он не позволяет
восстановить состояние соединений во время первоначального сбоя.

## Что проверено

- На production невалидные тела 250 355 и 326 669 байт получили JSON 400.
- Невалидные 326 669 байт по HTTP/2 получили JSON 400.
- Валидный WebM/Opus на 4 с, дополненный EBML Void до 326 669 байт, получил
  JSON 422 `audio_too_short` по HTTP/2 за 2,53 с. Предварительно проверено, что
  он действительно короче 5 с. Ни одна из этих проверок не создала отзыв или ASR-задание.
- Локальные реальные Uvicorn Guide → Voice и изолированные PostgreSQL:
  четырe варианта raw WAV на 20,28 с — с Content-Length / chunked, пользователь /
  администратор — получили 202 и ровно одну сохранённую отправку каждый.
- Локальный Chromium с MediaRecorder и синтетическим источником AudioContext:
  20,28 с, WebM/Opus, 68 chunks / 327 741 байт → 202 за 225 мс.
  ASR-worker не запускался.

## Что пока не установлено

Корневая причина 504 не воспроизведена. Существующее событие `received` означает
получение заголовков, а не всего аудио. Между ним и итоговым ответом нет этапов,
которые отделяют чтение тела запроса, подготовку контекста и вызов Voice.
Увеличение nginx timeout не является доказанным исправлением.

Журнал `voice_upload_http` уже хранится в существующей таблице `audit`, но экран
`/guide/logs` читает только задания наполнения. Предложен просмотр этих событий
на том же экране, с группировкой по `audit.target` (HTTP request_id), без новой
таблицы и без повторного запуска записи. HTML/CSS-макет показан владельцу;
полноценная реализация интерфейса ожидает согласования по AGENTS.md.
