# Проверка самостоятельного поиска городских окрестностей

Это проверка промпта, а не заранее заданные рестораны для наполнения.
JSON ниже — снимок первой API-попытки, до добавления обязательного поиска по
окружающим территориям перед фиксацией десятки. Он сохраняется как история попытки,
не как актуальный шаблон. [Текущий промпт](../../../data/prompts/restaurant-research-v4.txt)
содержит новый порядок поиска и отдельное правило для небольших/удалённых городов.
Входы получены через `JobService.process` / `OpenAIProvider.generate` на изолированной
локальной БД, с пустым `coverage_note`. Тестовый транспорт только перехватил полный
запрос; затем эти JSON отправлены в реальный Responses API. Заголовки авторизации
не сохраняются. Модель — `gpt-4.1` (значение по умолчанию приложения),
`web_search_preview`, `generation_v4`, до 32000 выходных токенов.

- [Анапа: полный запрос](anapa-request.json). Ожидаем самостоятельно найти «Винотеррию».
- [Медвежьегорск: полный запрос](medvezhegorsk-request.json). Ожидаем самостоятельно
  найти «Руну» при отеле «Заонежье».

В запросах нет этих названий, их сайтов, Семигорья, Кажмы или Заонежья.
Ожидаемый результат хранится только в этом документе и тестовых данных.

## Результат первой попытки

Оба POST `/v1/responses` вернули HTTP 401, `invalid_api_key`.
Генерация не состоялась: нет результата поиска, статуса проверки или тройки.
**Качество общего промпта на этих примерах пока не подтверждено.**
Доступ GET к карточке модели не доказывает работоспособность генерации.
Нужно повторить эти входы через действующее подключение, сохранив полный ответ.
Production-города, отзывы и заполненные страницы не менялись.

После успешного доступа отдельно проверить: (1) ресторан обнаружен,
(2) подтверждены обязательные факты, (3) ресторан вошёл в тройку после серверного
ранжирования. При пропуске исправлять общие инструкции поиска, без подстановки
ожидаемого ресторана, сайта или точной деревни в запрос.

Диагностический поиск в текущем чате, где ожидаемые рестораны уже известны,
показал разницу: «Винотеррия» появляется при общем поиске окрестностей Анапы,
а «Руна» — после перехода от городских результатов Медвежьегорска к Заонежью.
Это не слепой тест и не проверка тройки. Он выявил причину усилить общий промпт:
сначала определить окружающие направления, отдельно исследовать их рестораны
и только затем выбрать десятку. API для этой диагностики не использовался.
