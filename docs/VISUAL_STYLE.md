# Визуальный язык Инвольта гида

Зафиксирован по публичному сайту и `src/involta_guide/web/static/style.css`
на 4 ноября 2026 года, код `67c1db6`. Алекс попросил сохранить и описать
сложившуюся стилистику. Это описание существующего языка; для голосового блока Алекс выбрал
**вариант №2 «Продолжение подборки»**, убрав лишние подписи под микрофоном.
Выбор зафиксирован, внедрение поручено Sol: [ТЗ](VOICE_WIDGET_DESIGN_SPEC.md).

## Характер

Лаконичный редакционный гид. Впечатление создают шрифт, пропорции, свободное
пространство и аккуратные линии. Страница читается как небольшая подборка,
у которой есть автор и вкус. Крупный заголовок привлекает внимание;
спокойный текст помогает решить, куда пойти. Интерфейс не перебивает содержание.

Рабочее название этого направления: **редакционный минимализм**. Это описание
дизайна, а не новый слоган для сайта.

## Две гарнитуры и их роли

| Роль | Текущее оформление |
| --- | --- |
| Основной текст, названия ресторанов, управление | `Arial, Helvetica, sans-serif` |
| Акцент в заголовке, слово «гид» в логотипе | Курсивная `Georgia, "Times New Roman", serif` |
| Номера ресторанов | Georgia, прямое начертание, приглушённый серый |
| Маленькие рубрики | Arial, uppercase, увеличенный межбуквенный интервал |

Характерный приём: «Где поесть» набрано гротеском, «в Иванове.» — курсивной
антиквой. Акцент занимает отдельное слово или короткую строку. Длинный основной
текст остаётся прямым, хорошо читаемым. Жирность не заменяет иерархию размеров.

Значения в публичном CSS:

- основной текст: 15 px / 1.6; описание ресторана: 16 px / 1.6;
- вступление города: 18 px / 1.6, ширина до 570 px;
- главный заголовок: `clamp(55px, 7.4vw, 104px)`, line-height 0.99,
  letter-spacing −0.075em;
- название ресторана: 38 px; заголовок раздела: 26 px;
- у обычных заголовков: font-weight 500, line-height 1.15,
  letter-spacing −0.04em;
- маленькая рубрика: 10 px, font-weight 600, letter-spacing 2 px;
- номер ресторана: 42 px, Georgia, цвет #999.

Это зафиксированные значения существующей страницы, а не требование использовать
главный заголовок 104 px внутри каждого блока. Новые элементы подчиняются
иерархии страницы. На телефоне проверяем реальные переносы русского текста.

## Цвет, линии и форма

| Токен | Значение | Назначение |
| --- | --- | --- |
| `--paper` | `#fff` | Основной фон |
| `--black` | `#151515` | Основной текст, основные действия, сильные разделители |
| `--muted` | `#747474` | Вспомогательный текст |
| `--line` | `#dededb` | Тонкие разделители |
| `--soft` | `#f5f5f2` | Второстепенная поверхность, уже существующая в CSS |

Публичная страница преимущественно белая. Серый служит для иерархии и разделения,
не становится самостоятельным декоративным акцентом. Разделитель — обычно 1 px.
Граница раздела может быть чёрной; границы отдельных ресторанов — светлыми.

Основные кнопки сайта плоские, тёмные, прямоугольные. Круглая кнопка микрофона —
отдельное согласованное решение для записи голоса: она остаётся круглой и по
центру доступной ширины. По прямому решению Алекса поиск на главной также получает
мягкие скругления и спокойную кнопку: жёсткая прямоугольная рамка и тяжёлый чёрный
блок здесь не подходят характеру гида. Новый [эталон поиска](design/location-search/reference-morph.html), присланный владельцем,
задаёт геометрию и движение. Кнопка выбора — «Выбери ↓», 21 px. Строка и подсказки образуют одну
оболочку: числовая высота и радиус 40→34 px меняются за 420 мс с
`cubic-bezier(.22,1,.36,1)`. Лёгкие нейтральные тени:
`0 2px 7px rgb(0 0 0 / 3.5%)` в покое, `0 4px 14px rgb(0 0 0 / 4.5%)` при раскрытии.
Кнопка `#2861eb` с белым «Выбери ↓» сжимается с 132×54 до 122×50 px,
надпись 21 px на всех ширинах (на телефоне ширина кнопки 114 px). Поле 22/16 px; до 360 px ведущая лупа скрыта.
Подсказки проявляются со сдвигом −6→0 px. Пропорции, цвета и движение берём
из присланного HTML с указанной правкой шрифта; контракт — [LOCATION_SEARCH.md](LOCATION_SEARCH.md).


Ссылки и небольшие стрелки `→` / `↗` встроены в текст. Для микрофона подходит
простой контурный SVG. Декоративные тени, градиенты, цветные плашки и новые
гарнитуры не входят в сложившийся язык.

## Пространство и композиция

- В публичной шапке остаётся логотип; слоган справа удалён по решению Алекса.
- В футере одна ссылка на «О проекте», до первого открытия — «Я тут в первый раз».
  Описание и вход в админку из футера удалены. Учёт cookie и статистика — [AUDIENCE.md](AUDIENCE.md).
  На самой странице «О проекте» футера нет: она заканчивается третьим блоком.
- Если расписания ресторана нет, блок часов и сообщение «Режим работы уточняется»
  не показываем. Известные часы отображаются как прежде.
- Страница построена по общей вертикальной сетке, края разделов совпадают.
- У основного `main` max-width 1232 px с боковыми отступами 48 px;
  у шапки max-width 1360 px. На узком экране используются адаптивные отступы.
- Верхний блок города имеет отступы 60/50 px. Рестораны разделены отступами 45 px
  и тонкими линиями; номер вынесен в отдельную колонку.
- Абзацы ограничены по ширине, даже когда вокруг много свободного места.
- Пустота помогает прочесть иерархию. Её не следует создавать за счёт невидимых
  контролов или большого резерва под другие состояния виджета.
- Центрирование подходит короткому приглашению к действию. Основная подборка
  сохраняет чтение слева направо с выравниванием по левому краю.

## Страница «О проекте» — утверждённый вариант

Алекс утвердил mobile-first страницу из трёх крупных текстовых блоков:
«Скажи / голосом.», «Тебя услышат / моментально.», «Повлияй / на рейтинг.».
Вторая строка каждого заголовка — курсивная Georgia, первая — Arial.
Номера шагов, отдельный верхний заголовок, вводный абзац, подпись автора,
кнопка после текста и футер отсутствуют. В шапке вместо «Россия» — «О проекте»;
логотип сохраняет переход на главную. Это исключение только для этой страницы.

На мобильном: боковые отступы 25 px, заголовки `clamp(36px, 10.7vw, 48px)`,
межстрочный интервал 1.04; описания чёрные, 17 px / 1.5. Между блоками тонкая
светлая линия. От 760 px: заголовки 60 px, описания 19 px, ширина страницы
не больше 720 px. Точный утверждённый текст находится в `about.html`.

Эталон и скриншоты реализации: [страница «О проекте»](design/about/README.md).
Тексты описывают продуктовый замысел владельца; этот визуальный PR не добавляет
чат и автоматическое изменение рейтинга по отзывам.

## Как встроить голосовой блок

Сейчас Shadow DOM виджета задаёт `system-ui`, тогда как сайт использует Arial.
Вся просьба выглядит одним заголовком 22–32 px. Кроме того, `.stage` резервирует
место под таймер и дополнительные действия даже в состоянии ожидания. Это
конкретные причины визуального отличия от окружающей страницы.

Для обсуждаемых макетов:

1. Сохраняем смысл и постоянно видимую просьбу:
   «Твой голос важен. Скажи, что ты думаешь и о каком ресторане».
2. Разделяем приглашение и инструкцию размерами/начертаниями. Не переносим
   инструкцию только в placeholder, tooltip или состояние записи.
3. Используем гарнитуры и цвета сайта. Курсив — осмысленный акцент.
4. Сохраняем круглый микрофон по центру и доступное имя кнопки через aria-label;
   видимую подпись «Записать отзыв» убираем.
5. В чистом idle оставляем просьбу и микрофон. Минимум 5 секунд объясняем при
   записи/слишком коротком аудио; поведение минимума сохраняется.
   Зона нажатия не меньше 44×44 px.
6. Статический макет не меняет запись, VAD, отправку, минимальную длительность,
   автоматическую отправку или восстановление записи.

Выбранный вариант потребуется отдельно применить к состояниям записи,
отправки, ожидания и ошибки: сохранять видимую просьбу, фокус и
стабильную позицию управления. Диагностика беты должна остаться доступной.
Прятать её в продукте на основании этих макетов не нужно.

Четыре предложения: [макеты голосового блока](design/voice-section/README.md).
Выбранный эталон: [№2 без лишних подписей](design/voice-section/screenshots/02-approved.png).
Рубрика и просьба выровнены слева, микрофон по центру блока.

## Главная и лента «Жизнь кипит»

Утверждён [макет главной](design/home-reviews-preview/index.html). Маленькая рубрика
«Еда. Люди. Качество.» сохраняет указанный регистр. Подпись «Куда отправимся?»
и описание под поиском удалены; доступное название поля — «Поиск локаций и ресторанов».
Подписи других форм, использующих тот же виджет, остаются видимыми.

Вместо сетки городов — 10 свежих публичных отзывов, заголовок «Жизнь кипит».
Одна колонка до 860 px, без карточек и заливок. Город — курсивная Georgia
19/17 px, тонкое подчёркивание и маленькая стрелка; дата и время справа,
12/11 px, серый текст и табличные цифры. Текст отзыва — Arial 17/16 px,
line-height 1.65, с сохранением абзацев. Вся строка открывает город.

Между отзывами тонкие разделители. Под последним отзывом и над футером главной
линий нет. Название ресторана не выводится до появления реальной привязки.
Примеры отзывов в HTML-макете демонстрационные; сайт читает reviews из PostgreSQL.

## Как работать дальше

Страница `/guide/for-agents` предназначена для подключения MCP по поручению
владельца: Arial/Georgia, белый фон, тонкие линии и моноширинные примеры.
Подключение объясняется на отдельной странице, основной футер не меняется.
Макет и скриншоты приложения: [MCP](design/mcp/README.md).

Перед изменением публичного интерфейса читать этот документ и смотреть текущую
страницу в браузере. Показывать Алексу HTML/CSS-макет на широкой и мобильной
ширине до внедрения. Для небольшого блока достаточно фрагмента с соседним
контекстом. Проверять читаемость, переносы, общую сетку, фокус и отсутствие
горизонтальной прокрутки. Состояния управления проверять отдельно от картинки.

При интеграции с Shadow DOM задавать тему явно; глобальный CSS сайта внутрь
него не проходит. Выбрать один источник значений темы при реализации, а не
поддерживать две постепенно расходящиеся палитры и типографики. Конкретный
механизм согласовать в задаче внедрения — макет не требует новой архитектуры.

После выбора Алекса обновить соответствующее правило и ссылку на эталонный
скриншот. Для админки действует также [ADMIN_DESIGN.md](ADMIN_DESIGN.md):
у рабочего интерфейса собственная плотность, при общей типографике и палитре.

## Смешанные подсказки

Владелец поручил смешать локации и опубликованные рестораны, затем оценить результат.
[Макет](design/hybrid-search/index.html): один список до восьми строк; локация
сохраняет уточнение, под рестораном только название города, без слова «Ресторан». При равной
точности — две локации и один ресторан; точное название выше приблизительного.
Серверные варианты дополняют мгновенную локальную выдачу, без «Ищем…». Под
указателем и при навигации клавиатурой строки не переставляются. Геометрия и
плавность капсулы, синяя кнопка «Выбери ↓» 21 px сохраняются.

Для подсветки владелец выбрал №2 из [пяти вариантов](design/search-highlight-options/index.html):
по бокам и снизу 8 px, нижние углы последней строки и области прокрутки 25 px.
Внутренний нижний контур согласован с оболочкой радиуса 34 px.
