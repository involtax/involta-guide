# Логи запросов

Единая страница: `/guide/logs`. Ссылка «Логи» есть в меню админки.
Слева — поиск, фильтр и список запросов, справа — выбранный лог.
Прокручивается вся страница; отдельной прокрутки у колонок или ответов нет.

Адреса: `/guide/logs/ivanovo/1`, `/guide/logs/ivanovo/1.json`.
Список города: `/guide/logs/ivanovo`. UUID не используются в новых ссылках,
именах файлов или формах выбора лога. Старые адреса только перенаправляют;
страницы «Аудит ИИ» больше нет.

## Идентификатор в PostgreSQL

Таблица `request_logs` хранит:

- `location_slug`, `number` — составной первичный ключ лога;
- `path` — сохранённый generated-путь `/logs/<slug>/<number>`;
- `job_id` — внутреннюю связь с существующей очередью, не адрес лога.

`location_slug` ссылается на `locations.slug` с `ON UPDATE CASCADE`.
Смена slug города обновляет ключи и сохранённые пути всех его логов в БД.
Номер назначается триггером PostgreSQL при создании запроса с блокировкой строки
локации. Это работает для генерации и обработки отзывов, включая конкурентные
запросы. Неудачные запросы остаются под своим номером.

Миграция `0003_logs` переносит старые запросы и сохраняет существующие номера
генерации. Другие старые запросы получают номера после уже выданных. Исходные
запросы, ответы, версии страниц и их идентичности не переписываются.

## Какие данные доступны

После входа администратор видит все запросы. Без входа видны только разрешённые
логи публичного/ручного наполнения: `generate` без отзыва с маркером
`temporary_public_fill` или `generation_run.public_log=true`. Подстановка номера
закрытого запроса не открывает его. Аудио `/logs/<slug>/<number>/audio` требует
административной сессии. При `PUBLIC_FILL_LOGS_ENABLED=false` администратор всё
равно видит логи после входа, публичный доступ закрыт.

Для каждого нового запроса сохраняются промт, модель, точный JSON запроса,
полный ответ провайдера, HTTP-статус, заголовки, request_id, токены, доступная оценка
стоимости, все попытки обработки, ошибки полей и traceback. Для голоса также
хранятся ссылка на аудио, размер, MIME, SHA-256, расшифровка и результат анализа.
Успешный запрос связан с созданной версией страницы; ошибка не создаёт пустую версию.

События пишутся в `audit` независимо от транзакции публикации: отказ валидации
не удаляет уже полученный ответ. В `ai_usage` хранится каждая генерация/операция API.
Проверки GET фоновой генерации сохраняются в хронологии, но не считаются новыми генерациями.
Его `status=done` означает получение/JSON-разбор ответа, а не успешную проверку
ресторанов. Итог находится в запросе и событии `job_failed`/`job_completed`.

API-ключи, пароли, секреты сессий, cookies и реквизиты БД скрываются. HTML
экранируется. Страницы и JSON отдаются без кеширования и индексации, с `Vary: Cookie`.
Для скачивания: `/guide/logs/ivanovo/1.json?download=1`, имя файла `log-ivanovo-1.json`.
Автоматического удаления истории нет. Ответы, которые раньше не записывались,
восстановлению не подлежат; аварийное завершение сохраняет только уже записанные события.

## Повтор запроса

Наполнение использует `background=true, store=true` в Responses API. Промт, модель,
схема, поиск и лимит ответа прежние. Таблица `generation_requests` связывает задание
с единственным POST, идентификатором ответа OpenAI, полным JSON и сроком ожидания.
Маркер отправки и резерв учёта создаются одной транзакцией до HTTP-запроса.
После получения ID обработчик освобождается, а очередь планирует только GET того
же ответа. Падение worker восстанавливается через lease; проверки не расходуют
`MAX_JOB_ATTEMPTS`. `GENERATION_POLL_SECONDS=10`, `GENERATION_WAIT_SECONDS=3600`,
`GENERATION_PARALLEL_LIMIT=2` — значения по умолчанию. Лимит параллельности общий
для обработчиков, проверяется под блокировкой PostgreSQL.

Каждый ответ HTTP сохраняется в аудит. Финальный JSON и usage сохраняются одной
транзакцией до проверки схемы и записи страницы. Таймаут/429/5xx при GET приводит
к следующей проверке того же ответа. После часа ожидание приостанавливается;
администратор может продолжить получение того же ID. Ошибки отправки с неизвестным
исходом (`unknown`) не повторяются автоматически. Ответы `failed`, `cancelled`,
`incomplete` сохраняются и останавливают задание, включая фактический usage.
Нулевая статистика без ответа API означает отсутствие данных, а не бесплатность.

При ошибке проверки доступна кнопка «Проверить сохранённый ответ повторно»:
текущий обработчик повторно проверяет исходный сохранённый JSON без API и нового
номера лога. Изменение актуальных данных по-прежнему блокирует перезапись; эту защиту повторная
проверка не отменяет. Закрытые логи и продолжение защищены сессией и CSRF.

Вверху лога показываются стадии обработки и отдельно факт публикации. Маленький
endpoint `/logs/<slug>/<number>/status` с теми же проверками доступа обновляет
статус каждые 10 секунд; исходные ответы не загружаются при каждом обновлении.
Кнопка «Обновить полный лог» открывает актуальную хронологию и действия.
Общая отмена очереди отменяет только ещё не начатые генерации, а не уже принятые OpenAI.

Для отката приложения схема сохраняется. При откате на релиз до поддержки
фоновых запросов скрипт деплоя автоматически приостанавливает активные фоновые
задания перед запуском старого worker: он не умеет продолжать их. ID и ответы
сохраняются, возобновление доступно после возвращения нового обработчика. Обычные последующие обновления
продолжают работу по сохранённым ID. Старые неудачные запросы автоматически
не возобновляются, а новая отправка из их лога создаёт следующий номер.

Модель выбирается на вкладке «Наполнение» или непосредственно у выбранного лога.
Каталог и цены: [MODEL_CATALOG.md](MODEL_CATALOG.md).
Выбор не меняет модель распознавания речи или анализа отзывов.

«Повторить новым запросом» создаёт следующий номер с текущим промтом и выбранной
моделью. Значения фиксируются при постановке задания; последующая смена настройки
не меняет уже поставленный запрос. Для заполненной страницы новый результат
после проверки сразу обновляет актуальные данные. При пустой странице повтор первоначального
публичного наполнения сохраняет поведение автопубликации после проверки.

Внешние переходы и формы повторов используют город и номер. Для старой страницы
админки с HTMX ответ `HX-Redirect` переводит браузер на канонический путь лога.

## Выкладка

Перед обновлением контейнеров deployment запускает `alembic upgrade head` из
целевого образа. На короткое время останавливаются web/worker Guide, затем
выполняется аддитивная миграция. При ошибке возвращаются прежние контейнеры;
деструктивный downgrade и удаление истории запрещены. Миграция проверена на
старой схеме с сохранёнными запросами, порядковыми номерами и сырыми ответами.

## Переобработка сохранённого ответа

«Переобработать тот же ответ» доступна администратору для полного сохранённого
ответа, в том числе после успешного применения. Она заново запускает разбор,
валидацию и применение локального сохранённого ответа без POST/GET к OpenAI.
Номер лога, исходный ответ и статистика обращения сохраняются; успешное применение
создаёт новую запись истории. Совпадающие рестораны сохраняют свои ID.

Текущая версия фиксируется при нажатии: устаревшая страница или последующая ручная
правка блокируют перезапись. При наличии активного задания сначала нужно дождаться
его завершения. Для незавершённого ответа остаётся отдельное действие продолжения
получения того же ответа по сохранённому ID.

## Полнота поиска

Отчёт «Поиск неполный» показывает учтённые, проверенные, исключённые и требующие
проверки места. Кандидаты и причины доступны прямо в логе. Завершение разбора ответа
не означает полноту исследования: успешный частичный результат имеет `status=done`,
но отдельный статус качества `partial` и заметную отметку в интерфейсе.
Подробности, совместимость и пример Переславля: [GENERATION_QUALITY.md](GENERATION_QUALITY.md).
