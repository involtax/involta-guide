# Читаемые URL локаций

Правила хранятся в Git: [transliteration.json](../src/involta_guide/domain/transliteration.json).
Это одна таблица букв, окончаний и исключений, которую читает Python.
Готовые адреса стартового справочника — [location-catalog.json](../data/location-catalog.json).
Рабочий адрес каждой локации хранится в PostgreSQL, поле `locations.slug`.

## Правила

| Что | Запись в URL | Пример |
| --- | --- | --- |
| ё | e | Плёс → `ples`, Орёл → `orel` |
| х | h | Химки → `himki` |
| щ | sch | Щёлково → `schelkovo` |
| -ий, -ый в конце слова | -y | Нижний Новгород → `nizhny-novgorod` |
| й | y | Бийск → `biysk`, Йошкар-Ола → `yoshkar-ola` |
| ж, ч, ш, ц | zh, ch, sh, ts | Без изменения |
| ю, я | yu, ya | Без изменения |
| ь, ъ | опускаются | Тверь → `tver` |
| Санкт-Петербург | spb | Явное исключение |

Москва остаётся `moskva`. Регистр приводится к нижнему, пробелы и разделители —
к одному дефису. Окончания меняются в каждом слове, но не внутри слова.
Редакционные сокращения, префиксы районов и суффиксы для одноимённых городов
в каталоге сохраняются. Полный список: [283 замены](LOCATION_SLUG_CHANGES.md).

## Новая локация и ручные правки

При создании локации можно оставить URL пустым: сервер предложит адрес по её
названию и сохранит его вместе с остальными полями. Можно сразу указать свой URL.
Если адрес занят, форма просит исправить его; автоматических числовых суффиксов нет.
При последующем редактировании имя само по себе не меняет адрес: URL редактируется
отдельно. Изменение JSON правил также не переименовывает существующие строки БД.

## Переход существующей базы

Миграция `readable_slugs` переименовывает 283 каталожных URL и два редакционных
алиаса. Её [фиксированный список замен](../migrations/data/readable_slugs.json)
нужен только для переноса существующих данных; приложение его не читает.

Миграция сначала проверяет все занятые адреса и только затем меняет данные одной
транзакцией. Конфликт с чужой локацией или алиасом останавливает весь перенос
с указанием адреса. Локации с уже изменённым вручную URL/названием/регионом
не переименовываются. Пустая база получает новые URL при обычном импорте каталога.

ID, родительские и соседние связи, вступления, рестораны и отзывы сохраняются.
`request_logs.location_slug` меняется через `ON UPDATE CASCADE`, его вычисляемый
`path` получает новый адрес. Каждая смена URL записывается в существующий `audit`.
Сырые исторические ответы провайдеров не переписываются.

**Обратной совместимости нет:** новые алиасы и редиректы для старых URL не создаются;
старые адреса страниц и логов возвращают 404. Существующие альтернативные названия
локаций (например, Лаура и Альпика для Газпром Поляны) остаются редакционными алиасами.

Обновление выполняется обычным деплоем: резервная копия БД, `alembic upgrade head`,
`guide seed`. При откате релиза восстанавливаются согласованные образ и резервная
копия БД; обратную массовую транслитерацию не пытаемся вычислять.
