# Превью ссылок в Telegram

Решение [issue #24](https://github.com/involtax/involta-guide/issues/24): для главной
Алекс выбрал **«Инвольта гид»** и **«Города. Места, где вкусно.»**, без эмодзи.
Короткое название и две короткие фразы убирают повтор «Россия» из превью.

`og:title`, `og:description`, `og:type=website` и `og:url` отдаются в серверном HTML.
Главная задаёт выбранный текст отдельно от поисковых `<title>` и meta description:
SEO-формулировки продолжают описывать ресторанный гид по России. Страницы локаций
используют собственные title/description, а не текст главной. `og:url` совпадает
с canonical и строится из настроенного SITE_URL, включая базовый путь /guide/;
параметры поиска и пагинации в него не входят.

Админка, логи и страницы ошибок не получают превью главной. Изображение, эмодзи
и отдельная модель данных для карточки не добавляются. Общая разметка метаданных —
`web/templates/open_graph.html`, подключается только главной и локациями.

## Приёмка после деплоя

1. Проверить исходный HTML `/guide/` и `/guide/ivanovo`: четыре OG-поля, абсолютный
   canonical URL, собственные тексты города. JavaScript для метаданных не нужен.
2. В Telegram открыть ссылки на главную и Иваново в своём «Избранном».
   Проверить узкую и широкую компоновку. Зафиксировать название/версию клиента
   и дату; приложить реальные скриншоты к issue или PR.
3. Если виден прежний текст, учитывать кеш Telegram: существующая карточка может
   не обновиться сразу после деплоя. Повторно проверить после обновления кеша.
   Число строк и оформление определяет клиент, метатеги их не фиксируют.

Проверка серверного HTML не заменяет проверку карточки в Telegram. До получения
реальных скриншотов соответствующие пункты issue остаются открытыми.
