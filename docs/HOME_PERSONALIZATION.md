# История локаций и будущая персонализация главной

## Реализовано: история в браузере

Успешное открытие канонической HTML-страницы `/guide/{slug}` записывает ID этой
локации в cookie `guide_recent_locations`. Это история просмотренных страниц,
без утверждения о физическом посещении города.

- До 20 уникальных положительных числовых ID, свежие первыми.
- Повторное открытие переносит ID в начало; двадцать первый вытесняет самый старый.
- Формат `622.34.467`: только ID и разделители, без имён, дат или отдельного UUID.
- `Max-Age=7776000`: 90 дней с последнего открытия любой страницы локации.
- Host-only, `Path=/guide` (настраиваемый base_path), `HttpOnly`, `SameSite=Lax`;
  `Secure` следует существующей настройке `COOKIE_SECURE`.
- Неверные/повторные значения отбрасываются; слишком длинная кука начинает новую
  историю с текущей локации. Значение занимает не более 219 символов.
- Главная, ввод поиска/каталог API, логи, админка, ошибки и редиректы историю
  не пополняют. При переходе через редирект учитывается конечная страница.
- Кука хранится в браузере; новой таблицы, записи истории на сервере, дополнительных
  запросов к БД и отдельного JavaScript нет. Очистка cookies очищает историю.

История просмотров работает и для администратора при открытии публичных локаций;
исключение его действий из статистики аудитории остаётся прежним.

Лента главной **сейчас не персонализируется**: прежние 10 опубликованных отзывов
из публичных активных локаций, новые сверху, включая ожидание распознавания.
Публичный HTML остаётся `private, no-store` с `Vary: Cookie`.

## Предложение: будущий алгоритм ленты — на рассмотрение

Ниже проект решения, а не реализованная сортировка. Окно 7 дней и одинаковый
приоритет всех 20 локаций предлагаются для согласования.

1. Взять те же доступные для главной отзывы, что и сейчас: `publication_status=1`,
   `status IN ('received','transcribed')`, активная публичная локация.
   Удалённые, ошибочные, неопубликованные отзывы и недоступные локации исключаются.
2. Прочитать до 20 ID из куки. ID, которых нет среди доступных локаций, ничего
   не добавляют в выдачу. Без истории — обычная общая хронология.
3. Первая группа: отзывы по этим локациям, созданные за последние 7 × 24 часа.
4. Вторая группа: все остальные доступные отзывы. Старый отзыв просмотренного
   города входит сюда на общих основаниях, а не получает бессрочный приоритет.
5. Сначала первая группа, затем вторая. Внутри каждой — `created_at DESC,
   number DESC`, как сейчас. Взять первые 10, каждый отзыв ровно один раз.

Все 20 локаций равноправны. Порядок в куке определяет только вытеснение старой
локации при новом просмотре; он не поднимает старый отзыв недавно открытого
города выше нового отзыва другого интересующего города. Рейтинг ресторанов
не меняется, соседние локации автоматически в интересы не добавляются.

Схема одной сортировки поверх **существующего фильтра доступности**:

```sql
ORDER BY
  CASE WHEN r.location_id = ANY(:recent_location_ids)
         AND r.created_at >= :cutoff
       THEN 0 ELSE 1 END,
  r.created_at DESC,
  r.number DESC
LIMIT 10
```

`:cutoff` — один момент текущего запроса минус 7 суток; ID передаются параметрами.
Отдельных лент/таблиц, сохранённых баллов и объединения с дублями не требуется.
Состояние «Расшифровка…» и публикация распознанного текста остаются прежними.

### Пример для просмотра

В истории: Медвежьегорск и Анапа. Москва не просматривалась.

| Отзыв | Возраст | Группа | Итоговое место |
| --- | --- | --- | --- |
| Медвежьегорск | 2 часа | Свежий по интересам | 1 |
| Анапа | 1 день | Свежий по интересам | 2 |
| Москва | 5 минут | Общая | 3 |
| Медвежьегорск | 9 дней | Общая | 4 |

Если свежих отзывов по интересам два, оставшиеся восемь мест заполняет общая
хронология. Если таких отзывов больше десяти — показываются десять самых новых
из первой группы. Если их нет — главная целиком совпадает с общей хронологией.

## Проверка хранения после выпуска

1. Открыть `/guide/anapa`, затем `/guide/medvezhegorsk`: в DevTools → Application →
   Cookies значение `guide_recent_locations` начинается с `622.34`.
2. Повторить Анапу: начало меняется на `34.622`, дубль не появляется.
3. Закрыть и снова открыть браузер/сохранённую сессию: история сохраняется.
4. Открыть главную, API-каталог или несуществующий адрес: история не меняется,
   хронологический порядок отзывов главной остаётся прежним.
5. В production проверить Secure и 90-дневный Max-Age; HttpOnly-кука видна в
   DevTools, но недоступна через `document.cookie`.

Проверки в коде: валидация/лимит, повторные открытия, отсутствие фонового наполнения
от HTTP GET, прежний порядок главной, отдельные Set-Cookie истории и аудитории,
реальное браузерное хранение и перенос в сохранённую сессию.
