# Административные маршруты

Реализация [ADMIN_ROUTES_SPEC.md](ADMIN_ROUTES_SPEC.md). Пути ниже относительны
`BASE_PATH` (обычно `/guide`). Доступ к административным экранам требует сессии,
запись — также same-origin и CSRF. Вход и выход остаются прежними.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/admin` | Обзор, счётчики, переходы к спискам и логам |
| GET | `/admin/locations` | Все локации; `q`, `status=all/empty/filled`, `page` |
| GET | `/admin/locations/new` | Создание локации |
| POST | `/admin/locations` | Сохранение новой локации |
| GET | `/admin/locations/export` | JSON-экспорт всех локаций |
| GET, POST | `/admin/locations/{slug}` | Данные и настройки города |
| POST | `/admin/locations/{slug}/intro` | Отдельное сохранение вступления |
| GET | `/admin/restaurants` | База ресторанов; `q`, `location={slug}`, `page` |
| GET | `/admin/restaurants/{number}` | Текущая карточка и связи с городами, без редактирования |
| GET, POST | `/admin/settings/filling` | Совместное сохранение промпта и модели будущих запросов |
| GET | `/admin/sessions` | Существующее управление сессиями |
| GET | `/logs`, `/logs/{slug}`, `/logs/{slug}/{number}` | Существующие логи и действия над конкретным запросом |

Для локаций слева доступны и пустые, и наполненные города. Сначала идут недавно
обновлённые; поиск и пагинация не меняют выбранную сущность в URL. Родитель и связи
выбираются по названию и slug. UUID остаются внутренними ключами, включая значения
передаваемых связей; их не нужно вводить вручную. Рестораны ранжируются по оценкам
текущей подборки, одобренным отзывам, звезде и названию, как прежде. Страница списка
показывает по 20 ресторанов; постоянный номер в ссылке не является позицией рейтинга.

Миграция `admin_routes` после `current_state` добавляет `restaurants.number`:
положительный глобальный `BIGINT GENERATED ALWAYS AS IDENTITY` с unique constraint.
Существующие записи получают номер при миграции, новые — атомарно в PostgreSQL.
Номер сохраняется при сортировке, переименовании и изменении связей. Пропуски допустимы.
Триггер смены slug больше не создаёт новые алиасы; FK логов каскадно обновляет slug,
а generated-поле пересчитывает пути. Старые алиасы из каталога остаются данными географии.

Вступление — отдельный источник изменения актуальной страницы. Сервис блокирует
строку, проверяет `revision`, меняет только `intro`, новую метку и время, а затем
в той же транзакции пишет `audit.action=manual_intro`. В detail — идентификатор
административной сессии и дифф `intro` before/after, без секретов и полных снимков.
Журнал доступен только в административной карточке. Неизменный текст не создаёт
событие. Конфликт сохраняет набранный текст рядом с текущим; повторное сохранение
использует свежую метку. Ранее запущенные генерации и пакеты сохраняют свои проверки
revision и не могут молча перезаписать правку.

Сохранение настроек наполнения не создаёт заданий и не меняет уже созданные.
Первичный запуск доступен только на публичной пустой странице; повтор, продолжение
и переобработка — в конкретном логе для администратора. Массовый enqueue и отмена
из настроек удалены вместе со старыми HTTP-ветками.

Старые `tab=overview/cities/locations/fill/restaurants/sessions/ai-audit`, выбранные
UUID в GET, `/admin/jobs`, оба прежних export URL и UUID-download аудита удалены
без перенаправления. Старые POST `location/attach/prompt/generation-model/generate/cancel`
не выполняются. Отзывы, оценки, телефоны и Voice сохраняют свои маршруты и контракты.

## Ручная проверка

После запуска ветки локально или в тестовом окружении:

- `/guide/admin`: войти; проверить переходы меню и счётчиков.
- `/guide/admin/locations?status=empty&q=Иваново`: пустой город виден; проверить страницы списка.
- `/guide/admin/locations/ivanovo`: изменить вступление, сохранить отдельной кнопкой,
  открыть `/guide/ivanovo`; проверить журнал. Во второй вкладке сохранить устаревшую
  форму: текст останется для сравнения, актуальные данные сохранятся.
- `/guide/admin/locations/new`: создать город, выбрать родителя/связи; экспорт
  `/guide/admin/locations/export` должен включать его. Изменить slug и проверить логи.
- `/guide/admin/restaurants?location=ivanovo`: открыть карточку по постоянному номеру,
  проверить ранжирование, связи, страницу 2 при наличии более 20 записей.
- `/guide/admin/settings/filling`: сохранить промпт/модель; в логах не должно появиться
  нового задания. На пустой публичной странице проверить первичный запуск только
  с тестовым провайдером. В существующем логе проверить повтор/продолжение/переобработку.
- `/guide/admin/sessions`: проверить список и завершение сессий.
- Проверить те же переходы на узком экране, reload, назад/вперёд и без JavaScript.

Эти адреса относятся к сборке из PR: production до отдельного деплоя их не получает.
Платные production-запросы для проверки не требуются.
