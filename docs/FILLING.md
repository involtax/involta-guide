# Наполнение города

Актуальный контракт: [независимое наполнение и закрытый API](INCREMENTAL_CONTENT.md).

Вступление, поиск ресторанов и исследование одного места — три независимых операции.
Каталог накапливается, отсутствующие в новом ответе места не удаляются. Оценки и
карточка обновляются отдельно. Балл и порядок рассчитываются сервером.
Прежняя схема «до 10 кандидатов → 3 сохранённых ресторана» больше не используется
для новых заданий; старый формат нужен только для сохранённых исторических ответов.

На странице пустого города остаётся временная кнопка «Запарсить эти данные».
Она запускает вступление и поиск; новые места затем исследуются в очереди.
Флаг `TEMPORARY_PUBLIC_FILL_ENABLED` выключает публичный вход, не отменяя принятые
задания. `PUBLIC_FILL_LOGS_ENABLED` управляет доступом к диагностике.
После появления опубликованных ресторанов существующий polling обновляет страницу.

Админка использует те же операции и правила, что закрытый API. Промпты и модель
настраиваются в `/guide/admin/settings/filling`. Фотографии/панорамы меняются в Git.
Удаления города/каталога через API наполнения нет.

Первое исследование использует `scope=all`: карточка перед оценкой. Отдельная
переоценка заготовки отклоняется до очереди; админка показывает для неё только
«Заполнить и оценить». Частичные подтверждённые факты сохраняются без оценки.
