# Версии CSS и JavaScript

Все CSS и JS, подключаемые HTML-шаблонами Guide, используют `settings.asset(path)`:

```jinja2
<link rel="stylesheet" href="{{ settings.asset('/assets/panorama.css') }}">
<script defer src="{{ settings.asset('/assets/panorama.js') }}"></script>
```

Результат: `/guide/assets/panorama.css?v=<RELEASE_SHA>`. `BASE_PATH` сохраняется;
версия берётся из существующей конфигурации релиза, отдельного реестра нет.
При новом релизе меняются URL ресурсов. При откате возвращаются URL его SHA.
Изображения, API и обычные ссылки остаются через `settings.path(...)`.
Голосовой виджет уже использовал `RELEASE_SHA`; теперь его URL собирает тот же метод.
В development значение версии — `development`: после локальной правки ресурса
нужна обычная перезагрузка с отключённым кешем в инструментах разработчика.

## Почему нельзя оставлять прежний URL

После PR #110 новый HTML содержал два изображения, но браузер мог использовать
старый `panorama.css`, где контейнер ещё был блочным. Пасхалка вставала под городом.
Статический сервер отдаёт Last-Modified/ETag; без явного срока свежести браузер
может применять эвристическое кеширование и не запрашивать файл при следующем
переходе. Новый HTML сам по себе не обновляет CSS и JS по прежним адресам.

Версия нужна обоим файлам: свежая раскладка со старым обработчиком жестов также
не образует согласованный интерфейс. Не помечаем URL `immutable`: сервер не хранит
исторические копии каждого ресурса. Уже открытая вкладка не обновляется сама;
новые версии подключаются при загрузке страницы.

## Проверки

- `tests/integration/test_asset_versions.py`: ссылки в реальном HTML, HTTP 200
  ресурсов, BASE_PATH, смена SHA и откат.
- `tests/e2e/test_asset_cache_upgrade.py`: сначала прогревает браузер старым
  CSS/JS по неверсионированным URL, затем открывает новое приложение в том же
  контексте. Проверяет горизонтальную раскладку, загрузку новых файлов и возврат.
  Chromium запускается в обычном CI; для дополнительного WebKit-прогона задайте
  `WEBKIT_EXECUTABLE` (путь к установленному Playwright-совместимому WebKit).
- WebKit с мобильным viewport не заменяет проверку на физическом iPhone или
  внутри приложения Telegram; такой прогон следует называть проверкой движка.
