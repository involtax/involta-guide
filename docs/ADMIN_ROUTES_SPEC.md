# ТЗ для sol2: ЧПУ админки, настройки наполнения и редактор вступления

Статус: согласованная задача на реализацию. Обновлено 2026-11-03.
База проверки: `main` на `a938d1faf92f5f15b5a899678f405672fba16ffc`.
Перед работой получить свежий `origin/main`: sol1 параллельно меняет Voice.

Этот документ заменяет предыдущие предложения по маршрутам админки. Последние
уточнения владельца: настройки наполнения остаются; запуск только с публичной
страницы города, повторные действия — из логов; отзывы не трогать; вступление
редактируется вручную; совместимость со старыми GET-адресами не нужна.

## 1. Цель и границы

Сделать понятные адреса и навигацию административных разделов, убрать массовое
наполнение и вернуть удобное редактирование вступления локации. Стек сохраняется:
Python, серверные HTML-шаблоны, HTMX, PostgreSQL. React не добавлять.

В этой задаче меняются локации, рестораны, настройки наполнения, обзор и сессии.
Отзывы, предложения, оценки, проверка телефонов и голосовые команды находятся
в зоне sol1: их модели, страницы, маршруты, модерацию и процессы не переделывать.
Сохранить существующие ссылки на эти разделы, даже если там пока старые адреса.
Не назначать sol2 новые `/admin/reviews/...` и не объединять Voice со старой
модерацией. Это отдельная работа sol1.

Никаких новых сущностей «версия страницы», «черновик», «снимок» и восстановления.
См. [CURRENT_STATE.md](CURRENT_STATE.md). Исключение из прежнего ограничения
на способы изменения страницы: **ручная правка вступления теперь разрешена**.
Обновить это правило в документации в рамках реализации.

## 2. Что уже есть — не реализовывать повторно

- Единая страница логов `/guide/logs` и адреса `/guide/logs/{slug}/{number}`.
- Административные действия на той же странице после авторизации; отдельная
  административная страница логов не нужна.
- Фильтры и статусы очереди в логах, сохранённые запросы и ответы, ошибки,
  повтор запроса и переобработка сохранённого ответа.
- Одна прокрутка страницы логов. На проверенной базе список запросов слева,
  содержимое справа. Перестановку колонок или редизайн в эту задачу не включать.
- Текущее содержимое локации без сохранённых версий; диффы наполнения и отзывов.

Проверить сохранность этого поведения при обновлении навигации. Не менять
разрешения логов: публичный доступ только к разрешённым логам наполнения,
закрытые данные и аудио не публиковать.

## 3. Таблица адресов

В таблице пути относительно `BASE_PATH`, сейчас `/guide`. Все ссылки, формы,
HTMX-запросы и редиректы строить через существующий помощник конфигурации пути.

| Метод и путь | Назначение |
| --- | --- |
| GET `/admin` | Обзор и навигация |
| GET `/admin/locations` | Все локации, поиск и фильтры |
| GET `/admin/locations/new` | Форма создания локации |
| POST `/admin/locations` | Создание локации |
| GET `/admin/locations/{slug}` | Данные и настройки локации, редактор вступления |
| POST `/admin/locations/{slug}` | Сохранение настроек локации |
| POST `/admin/locations/{slug}/intro` | Сохранение вступления |
| GET `/admin/restaurants` | База ресторанов, первый наполненный город |
| GET `/admin/restaurants/{slug}` | Рестораны выбранного города |
| GET `/admin/restaurants/{number}` | Карточка ресторана и связи с локациями |
| GET `/admin/settings/filling` | Раздел «Настройки наполнения» |
| POST `/admin/settings/filling` | Сохранение промпта и модели наполнения |
| GET `/admin/sessions` | Существующее управление сессиями |
| GET `/logs` | Существующий общий журнал |
| GET `/logs/{slug}` | Существующие логи локации |
| GET `/logs/{slug}/{number}` | Существующий конкретный лог |

Существующие вход/выход и служебные endpoints логов сохранить, если они уже
имеют понятный путь и не требуют изменения. Экспорт локаций сохранить, указать
его окончательный маршрут в таблице реализованных маршрутов. Статические пути
`new`, `export` и подобные не должны попадать в обработчик slug.

### Идентификаторы и GET-параметры

- Для выбранной локации использовать slug в пути.
- Ресторан получает постоянный публичный положительный номер в БД, уникальный
  глобально. Не использовать позицию в списке или номер, меняющийся при сортировке.
  Назначение безопасно при конкурентном создании. UUID как внутренний PK допустим.
- UUID не показывать в новых пользовательских адресах, подписях или полях выбора.
  Внутренние FK и технические значения формы не требуют тотальной замены.
- GET-параметры задают только опции выбранного экраном пути: `q`, `status`, `page`.
  Локация — в пути: `/admin/restaurants/ivanovo?page=2`. Неизвестные параметры игнорируются.
- Статус наполненности списка локаций: все / пустые / заполненные. Пустые
  локации должны быть доступны из админки, а не скрыты списком «Готовые города».
- Смена slug обновляет ссылки и уже существующие пути логов в БД. Старый slug
  сохранять как алиас или редирект не требуется.
- Не хранить собранные URL там, где достаточно slug/номера. Существующий
  generated-путь логов и его целостность сохранить.

### Старые адреса удаляются, совместимости нет

Удалить диспетчеризацию `?tab=...` целиком, выбор сущностей через UUID/query,
устаревшие aliases и обработчики перенаправлений. `/admin` всегда обзор (без
сессии — вход); произвольные query, включая старый `tab`, не меняют экран и не
вызывают 400/404/редирект. Неизвестный путь возвращает 404.

Не добавлять таблицы соответствия, compatibility middleware, временные редиректы
или поддержку старых закладок. Удалены и старые `/admin/voice/...` aliases: код
отзывов уже использует `/admin/reviews/...`. Новое решение владельца заменяет
прежнее временное исключение для sol1 и требование отклонять `?tab=`.
Подсветка меню и шаблон определяются внутренним `active_section` обработчика.

Проверить поиск по репозиторию: ссылки, формы, HTMX, тесты, документацию и
старые POST-ветки, если действие полностью перенесено на новый endpoint.
Особенно удалить массовую генерацию на backend, а не только спрятать кнопку.

## 4. Наполнение: только осознанный запуск для одной локации

### Раздел «Настройки наполнения» остаётся

Маршрут `/admin/settings/filling`, название в меню «Настройки наполнения».
Здесь находятся редактируемый промпт первичного наполнения, выбор модели из
каталога и существующие пояснения/цены. Сохранение настроек не запускает запрос.
Новые задания фиксируют промпт и модель при создании; уже созданные не меняются.
Настройки распознавания/анализа отзывов сюда не переносить.

### Откуда разрешён запуск

1. Публичная страница пустой локации `/{slug}`: существующая кнопка
   «Запарсить эти данные», доступная всем в текущем временном режиме MVP.
   Это единственная точка первичного запуска. Сохранить действующий feature flag,
   не вводить для неё новую авторизацию. После успешного наполнения кнопка исчезает.
2. Конкретный лог: авторизованный администратор вручную повторяет запрос,
   продолжает получение ответа либо переобрабатывает сохранённый ответ.
   Сохранить существующую семантику каждого действия и выбор модели для нового
   запроса. Ошибка должна оставлять доступный лог и понятную ссылку на него.

В административной карточке города **нет** кнопки генерации. Есть ссылка
«Открыть страницу» и ссылка `/logs/{slug}`. Из пустого города администратор
переходит на публичную страницу и запускает наполнение там.

### Что удалить

- Массовый запуск «Все локации» / «Пустые локации», постановку городов списком.
- Кнопку генерации внутри административной карточки локации.
- Отдельный экран ручного набора очереди, массовую отмену генераций из настроек.
- Кнопки запуска из обзора, обходящие публичную страницу локации.
- Backend-ветки и вспомогательные функции исключительно для этих массовых
  операций; не оставлять возможность вызвать их прямым POST.

**Внутренняя очередь остаётся:** worker, фоновые запросы, polling, lease, лимиты,
аварийное восстановление и статусы. Нельзя заменять фоновые запросы синхронным
ожиданием HTTP. Очередь видна в существующих логах через фильтры статуса.
Отзывные задания и их управление не трогать. Не отменять уже выполняющиеся
задания при открытии экрана или сохранении настроек.

Сохранить защиту от дублирования активного наполнения одной локации, включая
конкурентные клики. GET страницы не запускает платный запрос.

## 5. Ручное редактирование вступления — обязательно

На `/admin/locations/{slug}` показать textarea с текущим вступлением и кнопку
«Сохранить вступление». После сохранения текст сразу виден на публичной странице.
Не требовать генерации, отзыва, одобрения, публикации или создания черновика.

Это третий легитимный источник изменения страницы: **ручное действие администратора**,
помимо наполнения и одобренного отзыва/голосовой команды. Нельзя создавать фиктивный
отзыв или фиктивное задание OpenAI ради ограничения существующего `editorial.save()`.

Требования к записи:

- Административная авторизация, CSRF и серверная валидация текста. Пользовательский
  HTML не исполняется; сохранить текущую модель безопасного отображения текста.
- Сохранить только актуальное `locations.intro`, не переписывать рестораны,
  порядок, рейтинги, отчёты и остальные настройки страницы.
- В одной транзакции проверить optimistic concurrency, изменить вступление,
  обновить текущую `revision`/время и записать событие ручного редактирования.
- Событие содержит локацию, время, доступную идентичность администратора/сессии
  без секретов, тип действия и дифф поля `intro` с `before`/`after`.
- Использовать существующий журнал аудита, если он подходит; при необходимости
  минимально расширить его. Не заводить хранилище версий или полных снимков страницы.
- Показывать эти события авторизованному администратору в карточке локации
  как журнал ручных правок вступления. Без восстановления и без публичного
  раскрытия административных идентификаторов. Не смешивать их с логами вызовов ИИ.
- При неизменном тексте не создавать фиктивный дифф и не менять revision.
- При конфликте не затирать свежие данные: показать понятную ошибку и сохранить
  введённый пользователем текст в форме для сравнения/повторного ввода.

Обновление revision обязательно: запущенная ранее генерация или пакет изменений
не должны незаметно перезаписать новую ручную правку. Не отключать существующие
проверки источника и целостности. Можно добавить узкий сервис правки вступления,
сохранив общий механизм блокировки/revision и не меняя контракт Voice.

## 6. Остальные экраны и организация кода

- В локации сохранить географию, видимость, надлокации, связи, число карточек
  до кнопки «Ещё». Вместо ручного ввода UUID родителя/связей дать выбор по названию
  и slug. Не перестраивать географическую модель и данные.
- В заголовке выбранного города на странице ресторанов дать ссылку на публичную
  `/{slug}` в новой вкладке, включая просмотр одной карточки. Она не использует HTMX.
- Карточка ресторана использует текущие данные и ссылки на локации; не добавлять
  новые права редактирования ресторана, звезды, телефона или модерации отзывов.
- Обзор показывает счётчики и ссылки на отфильтрованные списки/логи, без генерации.
- Маршруты HTTP тонкие: чтение/валидация/вызов сервиса/ответ. Бизнес-операции и
  транзакции не переносить в шаблоны. Не создавать универсальный framework роутинга.
- Общую навигацию обновить минимально; в файлах, которые меняет sol1, сохранять
  его изменения. Перед PR сверить свежий main и разрешить конфликты осмысленно.
- Сохранить вход/выход, CSRF, HTMX и работу без JS, где уже поддерживается.

## 7. Проверки приёмки

1. Каждый новый GET открывается напрямую и после reload; работают навигация,
   история браузера, фильтры, пагинация и HTMX без подмены полного HTML фрагментом.
2. Новые ссылки не используют `tab` или UUID; выбранная сущность отражена в пути.
   Старые адреса переработанных разделов не поддерживаются и не перенаправляются.
3. Настройки наполнения сохраняют промпт/модель без задания и без API-вызова.
   Массовых запусков нет ни в UI, ни через старый POST.
4. Публичная кнопка пустого города создаёт одно фоновое задание; конкурентный
   повтор не создаёт дубликат. Заполненный город не позволяет первичный запуск.
   Ошибка доступна в логе; повторные действия администратора из лога работают.
5. Вступление меняется сразу; рестораны и отчёты неизменны. Дифф и текущие данные
   атомарны; конфликт и no-op проверены. Устаревшая генерация не затирает правку.
6. Защищённые POST недоступны без сессии/CSRF; редактор не делает логи/аудио
   отзывов публичными. Проверить экранирование вступления.
7. ЧПУ логов, пагинация и права сохранены. Не появляется отдельный `/admin/logs`.
8. Пустые локации видны в списке; смена slug обновляет ссылки/логи; номер ресторана
   стабилен при фильтрации, переименовании и привязке к нескольким локациям.
9. Проверить стандартный `/guide` и иной настроенный префикс. Контракт 302
   `/guide` → `/guide/` и маршруты основного сайта сохранить.
10. Запустить принятые в репозитории lint/typecheck/тесты; добавить проверки
    существенного поведения, выполнить браузерную проверку desktop/mobile.
    Для тестов использовать fixtures/mocks, не запускать платные генерации на проде.

## 8. Документация и доставка

Работать в отдельной ветке от свежего `origin/main`. Не запускать других агентов
для Voice и не откатывать изменения sol1. Документ этот включить в свою ветку.

По завершении обновить `CURRENT_STATE.md`, `LOGS.md`, документацию временной
публичной кнопки и список legacy: удалить устаревшие обещания совместимости,
упоминания массового наполнения и запрета ручного редактирования вступления.
Не восстанавливать старые цепочки миграций. Если для номера ресторана/аудита
нужно изменение схемы — сделать минимальный рабочий переход от актуального
production-состояния и проверить чистую установку, сохранив текущие данные.

Открыть PR. В описании: итоговая таблица реализованных маршрутов, что удалено,
изменения схемы, результаты проверок и короткий сценарий ручной приёмки со
ссылками. Реальный production-деплой в эту задачу не входит.
