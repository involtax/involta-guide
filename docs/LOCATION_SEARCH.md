# Поиск локаций

Утверждённый вид: поиск под H1, единая капсула Б, «Фарфор», кнопка `#1477cf`
с белым «Найти» 22 px. На компьютере поле 80 px, кнопка 116 × 58 px, равные
зазоры 10 px; на телефоне 70 px, кнопка 100 × 50 px, зазоры 9 px.
История выбора — [макеты](design/location-search/README.md).

CSS и JS только в справочнике. Локальная autoComplete.js 10.2.10 с Apache-2.0
LICENSE: 9 367 байт (~3,8 КБ gzip). Адаптер и тема Guide отдельные;
демо-переключателей в публичном коде нет.

От двух символов, пауза 180 мс, максимум шесть подсказок. Название, тип, родитель
и регион различают одноимённые места. Выбор мышью/касанием либо стрелками/Enter
открывает каноническую страницу. Enter без выбора, «Найти» и «Все результаты»
отправляют обычную GET-форму. Без JS поиск работает. Escape сохраняет ввод.
Пустая выдача, ожидание и ошибка различаются; информационные строки не выбираются.
Первый результат автоматически не выбирается. Данные выводятся текстовыми узлами.

Поколение запроса и AbortController меняются при вводе, закрытии, очистке,
отправке и потере фокуса. Старый ответ игнорируется даже при неработающей отмене;
IME-композиция не запускает запросы. Панель учитывает visualViewport, при нехватке
места поле прокручивается в видимую область. Проверен Chromium на 390 px;
реальную клавиатуру iOS/Android следует проверить на устройстве.

## API и ранжирование

`GET /guide/api/locations/suggest?q=плес`:

```json
{"items":[{"name":"Плёс","context":"Город · Ивановская область","url":"/guide/plyos"}]}
```

Только эти поля, LIMIT 6, без COUNT. q до 100 символов; пустой/короткий
нормализованный запрос возвращает items: [] без SQL. API не создаёт cookies,
не увеличивает статистику и не запускает наполнение/AI. Fetch использует
`credentials: 'omit'`, HTTP-кеш 30 с. SQL параметризован, лимит 500 мс;
wildcard-символы удаляются нормализацией, ввод не вставляется в текст SQL.

Полная форма и подсказки используют один алгоритм. Админский поиск прежний.
Источник — locations, без копии каталога. Видимость повторяет PUBLIC-правило:
активные listed-локации, наполненные активные локации и их полезные предки.

Точное название → точный алиас → начало слова в названии → начало слова в алиасе
→ прочее совпадение в названии/алиасах → контекст. При равной релевантности выше
наполненные страницы, затем приоритет и стабильный name/id. Регистр, е/ё и
разделители нормализуются, слова можно переставлять. Slug поддерживает сохранённые
латинские написания; отсутствующие алиасы и транслитерация не выдумываются.

После пустого прямого поиска: английская раскладка (`cjxb` → «сочи»), затем
для запроса от четырёх символов — pg_trgm по названию с порогом 0,45.
Слабые похожести не предлагаются. Запасной запрос только после пустого результата;
пагинация и COUNT только на полной странице поиска.

## Миграция

`location_suggestions` после `audience_stats`: штатный pg_trgm в public и GIN
по `translate(lower(name),'ё','е')`. Нужны права установки trusted extension.
Downgrade удаляет только индекс, общая extension остаётся. Каталог не меняется.
Индекс включается в штатный pg_dump/restore вместе с locations. Новых таблиц нет.

EXPLAIN ANALYZE на тестовом каталоге: прямой запрос — один SELECT около 8 мс;
раскладка — два SELECT примерно по 7 мс; опечатка — прямой около 7 мс и запасной
около 3 мс. Это локальные SQL-замеры, не production SLA. Для маленького каталога
планировщик может предпочесть сканирование вместо GIN; его не перенастраиваем.
