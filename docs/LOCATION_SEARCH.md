# Поиск локаций

По прямому решению владельца поиск работает локально по небольшому каталогу.
**Совпадения только по названию самой локации.** Регион, родитель, тип, slug и
алиасы не участвуют в поиске. Подпись с регионом/типом нужна лишь для различения
одноимённых мест в выдаче.

## Загрузка и хранение

```text
GET главной → один SELECT публичного каталога → JSON внутри HTML
            → индекс в памяти браузера → поиск при каждом вводе без сети
```

Снимок содержит только `name`, `context`, `url`. Он передаётся через безопасный
Jinja `tojson` в `<script type="application/json" id="location-catalogue">`.
Отдельной загрузки, API подсказок, debounce, «Ищем…», fetch и таймеров запросов нет.
Данные готовы вместе со страницей; нормализация названий и триграммы вычисляются
однократно при создании индекса. До первого следующего кадра после ввода уже
есть окончательные подсказки, а не промежуточное состояние ожидания.

Кеш — память открытой страницы. При перезагрузке приходит свежий снимок
PostgreSQL: изменения имени, состава и видимости не требуют очистки localStorage,
TTL или серверного кеша. Открытая страница хранит свой снимок до обновления;
доступ к выбранной странице всё равно проверяется сервером. Служебные поля,
содержимое подборок, админские данные и алиасы в снимок не входят.

Видимость повторяет PUBLIC-правило: активные listed-локации, наполненные активные
локации и их полезные активные предки. Одним SELECT сервер задаёт исходный порядок:
готовые подборки, приоритет, name/id. Служебные признаки ранжирования не публикуются.

## Правила поиска

- Одна–две буквы: начало полного названия. От трёх: вхождение в любое место
  названия, все введённые слова должны присутствовать, порядок слов свободный.
- Регистр, е/ё, Unicode NFKC и разделители нормализуются.
- Выше точное название, затем начало слов, затем прочие вхождения;
  при равенстве сохраняется исходный серверный порядок.
- Если прямого совпадения нет, проверяется английская раскладка (`cjxb` → «сочи»),
  затем для запросов от четырёх символов — триграммная похожесть названия от 0,45.
  Это тоже локальные вычисления, без запросов и дополнительных библиотек.
- Подсказок не больше шести. Пустой ввод схлопывает блок. Потеря фокуса и Escape
  сохраняют текст и раскрытие. Крестик очищает и возвращает фокус. Первый вариант
  автоматически не выбирается; стрелки/Enter, мышь и touch открывают страницу.
- «Найти» и Enter без выбранного варианта отправляют GET на эту же главную.
  Ссылки «Все результаты» нет. Без JS обычная форма работает тем же поиском по
  названиям в Python. Соответствие двух реализаций проверяется на реальном каталоге.
- IME не меняет выдачу до завершения композиции. Названия выводятся текстовыми
  узлами; `<script>`/HTML внутри названий не исполняются.

`location-index.js` отделён от DOM-адаптера. Локальная autoComplete.js 10.2.10
(Apache-2.0, 9 367 байт / ~3,8 КБ gzip) управляет списком, ARIA и выбором.
CDN, сборки frontend и новых сервисов нет. Полнотекстовый SQL, pg_trgm и новая
миграция поиска больше не нужны; не выпущенная `location_suggestions` удалена.
Alembic остаётся на `audience_stats`. Админский поиск не меняется.

## Внешний вид

[Эталон владельца](design/location-search/reference-morph.html) задаёт морфинг:
единая оболочка строки/подсказок, закрытая высота 80 px, радиус 40→34 px,
числовая высота за 420 мс, `cubic-bezier(.22,1,.36,1)`. Тени
`0 2px 7px rgb(0 0 0 / 3.5%)` → `0 4px 14px rgb(0 0 0 / 4.5%)`.
Панель проявляется за 180 мс со сдвигом −6→0 px. Кнопка #2861eb сжимается
132×54→122×50 px, радиус 27→25 px; по следующей правке владельца «Найти»
22 px на всех ширинах. До 600 px ширина кнопки 82 px, поле 16 вместо 22 px.

При закрытии панель сразу получает inert/aria-hidden, после анимации hidden;
повторное раскрытие разворачивает текущий переход. ResizeObserver отслеживает
содержимое, visualViewport ограничивает высоту списка. Поле прокручивается в
видимую область только при фокусе. Reduced-motion практически отключает переходы.
Реальная клавиатура iOS/Android требует проверки на устройстве.

## Замеры

В каталоге репозитория 1448 записей, из них 1318 listed. Публичный JSON с тремя
полями занимает 162 329 байт UTF-8, 20 943 байта при gzip (сжатие зависит от
HTTP-сервера). На локальном Chromium для 5001 названия: создание индекса ~20 мс,
медиана поиска 0,2 мс, p95 0,4 мс в серии 100 запросов. Это локальные замеры,
не гарантия времени на каждом телефоне. Браузерный тест проверяет результат
до первого следующего кадра после ввода и работу с отключённым интернетом.

[Самодостаточная демка](design/location-search/approved-demo.html) использует
реальные CSS, библиотеку, индекс и адаптер с небольшим тестовым списком.
В ней нет fetch и искусственных задержек. [История макетов](design/location-search/README.md).

## Повторное использование в админке

`location_search.html` — один шаблон виджета для главной и «Рядом» в редакторе
локации. CSS и индекс поиска общие. DOM-адаптер монтирует формы при загрузке и
после HTMX; обработчики viewport и ResizeObserver освобождаются перед удалением.
Публичный snapshot по-прежнему содержит только name/context/url. В закрытой
админке каталог дополнительно содержит числовой id; выбор отправляет его в
защищённый POST добавления. Нативная форма использует тот же Python-поиск.
