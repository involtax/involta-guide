# Поиск локаций и опубликованных ресторанов

Решение владельца: мгновенные локальные подсказки дополнены фоновым поиском
по нашему каталогу. Поиск в интернете и запуск наполнения по вводу запрещены.
Ищутся названия локаций и опубликованных ресторанов, существующие альтернативные
названия локаций и явные общеупотребительные сокращения. Регионы, кухня, блюда,
описания, отзывы и служебный охват не участвуют.

## Поток и хранение

```text
Открытие → GET /api/locations/catalogue → компактный словарь в памяти
Ввод     → локальные локации сразу
Пауза 300 мс, ≥2 символа → POST /api/search → локации + рестораны
                        → один список до 8 вариантов
Показ/выбор/уход         → POST /api/search/events → search_attempts
```

Каталог локаций по-прежнему содержит только name/location/context. location —
slug без /guide/; в подписи города нет слова «Город». Одна отдельная загрузка
без cookies, ETag/304 с перепроверкой, предел ожидания 5 секунд. При наборе нет
повторных загрузок каталога. Нормализация локального индекса и триграммы строятся
один раз. LocalStorage и дополнительных сервисов нет.

Новая буква отменяет таймер 300 мс и предыдущий fetch; номер ввода меняется сразу,
а не после отправки. Только ответ для текущего номера может попасть в выдачу.
Отмена fetch не доказывает остановку серверной обработки. Успешные ответы для
50 последних нормализованных запросов кешируются в памяти страницы; ошибки нет.
Во время IME-композиции новый поиск не запускается. Пробелы/регистр/ё не вызывают
повторного запроса для того же нормализованного текста.

Сервер одним SELECT читает существующие публичные локации и активные рестораны
наполненных активных локаций, без надлокаций и сбрасываемых подборок. Скрытые
неопубликованные рестораны не ищутся. Источники актуальны на каждом запросе;
отдельной таблицы копий карточек/периодического обновления индекса нет.

Для текущего объёма используются уже установленные RapidFuzz и pymorphy3.
Кешируются только ограниченные производные нормализации слов/названий, а не
состав/видимость каталога. Нового поискового сервера, расширения PostgreSQL и
дублирующего поискового хранилища не требуется. Локальный замер: первый поиск
по 1448 названиям с инициализацией морфологии ~250 мс; сопоставление 5001 записи (повторённый каталог)
в серии запросов — медиана ~13 мс, максимум ~30 мс (без SQL/сети).
Это измерение конкретного окружения, не гарантия задержки на каждом сервере.

## Сопоставление и порядок

- Локально 1–2 буквы — начало полного названия, от трёх — вхождение слов.
- Сервер: точное название, начало слов, словарные формы, вхождения, опечатки.
  Русская морфология учитывает известные разборы, включая неоднозначные
  «Иванове» → Иваново. Неизвестные бренды не заменяются выдуманными леммами.
- Опечатки: от 4 букв, до одной операции для короткого слова и до двух от 7 букв,
  включая перестановку соседних букв. На 1–3 буквах нечёткий поиск не применяется.
- е/ё, регистр, NFKC, разделители нормализуются. Поддержаны неверная раскладка,
  транслитерация названия, варианты URL-транслитерации, aliases локаций и явные
  сокращения (Питер/СПб/Петербург/МСК). Slug сам по себе не является искомым полем.
- Служебные слова обычной фразы снимаются: «где поесть в Иванове» → Иваново.
  «Пушкин Туле» ищет название ресторана с уточнением города; одно только имя
  города не выдаёт все его рестораны. Регион не становится поисковым полем.
- Результат содержит стабильный id, kind, name, location, context, anchor,
  причину совпадения match и rank. Закрытые признаки/aliases в ответ не входят.
- Между источниками убираются дубли по id. Релевантность важнее типа; внутри
  равной точности чередуются две локации и один ресторан. До восьми строк.
- При выделении клавиатурой или наведении мышью уже показанные позиции
  сохраняются; дополнения занимают оставшиеся места. Следующий ввод пересчитывает
  порядок. Первый вариант автоматически не выбирается.

## Интерфейс и переход

Капсула, единая поверхность подсказок, фарфоровые тени и морфинг 80 px / радиус
40→34 px за 420 мс сохраняются. Синяя #2861eb кнопка «Выбери ↓», шрифт 21 px;
мобильная ширина 114 px, до 360 px ведущая лупа скрыта. Публичная подсказка поля —
«Локация или ресторан», доступное название — «Поиск локаций и ресторанов».
У ресторана подпись «Ресторан · город», у локации — прежнее уточнение.

Локальные варианты появляются без ожидания сервера. Пока сервер не ответил,
ложное «ничего не найдено» не показывается. При сетевом сбое локальные варианты
остаются доступны; ошибка не превращается в пустую выдачу, кнопку можно использовать
для повторной попытки. Ни одна ошибка не запускает обычную поисковую GET-форму.

«Выбери ↓»/Enter без выделения раскрывают список, пустой ввод — первые восемь
локаций. Переход — только по выбору: локация ведёт на её страницу, ресторан —
на неё же с #restaurant-UUID. Если карточка внутри закрытого details, он раскрывается.
Потеря фокуса плавно закрывает панель, текст остаётся; возврат фокуса раскрывает
снова. Escape сохраняет состояние, крестик очищает. Без JS публичный контрол
не отправляет GET. Страниц выдачи/пагинации нет; `/guide` →302 со сохранением query,
затем `/guide/` →308 без параметров. Навигация проверяет origin и базовый путь.

## Статистика и внешний анализ

Одна строка search_attempts на запрос, на котором задержались 300 мс или выбрали
результат. Быстрый промежуточный набор не записывается побуквенно. Локальный клик
до отправки фонового запроса тоже записывается. Хранятся исходный запрос, время,
полный IP, версии серверного алгоритма и показанной выдачи, серверный
результат/задержка, фактически показанный список,
признак его завершённости, выбранный id и причина завершения. Позиция клика
вычисляется из показанного списка. Доставка событий браузера может потеряться;
отсутствие клика — наблюдение, а не доказательство плохой выдачи.

Серверная запись и клиентский показ — разные наблюдения. Пустой ответ сервера
при наличии локальных подсказок не считается пустой выдачей. Не показанный ответ
не считается просмотренным. Приходят только реальные снимки показанного списка;
отдельно сохраняется ошибка, уточнение запроса, уход без клика или выбор.
Незавершённый показ старше 30 секунд без клика помечается «без клика», но поздний
клик может изменить итог. Это не таймер удаления истории.

Кеш хранит версию полученного ответа: после деплоя старая открытая страница
не приписывает кешированные результаты новой версии алгоритма.

Клиентский token — случайный UUID, доступный только этой странице; публичный
журнал выдаёт отдельный числовой id, не token. События имеют возрастающий seq;
повторы/поздние события не стирают клик, ответ сервера не перезаписывает показ.
POST проверяет Origin. Админский признак определяется действующей сессией,
не присланным флагом. Админские запросы сохраняются, обычные итоги их исключают.

По прямому решению владельца **история хранится без срока удаления**, включая IP.
Полный IP берётся сервером; X-Forwarded-For учитывается только от доверенного
прокси. Публичный HTML/JSON маскирует IP до IPv4 /24 или IPv6 /48. Cookie посетителя,
user-agent, заголовки и постоянный идентификатор человека не сохраняются.

`/guide/logs/search` и `.json` доступны извне в бете через общий флаг диагностики.
Есть фильтры пустой выдачи, отсутствия клика, ошибки, уточнения, выбора; общие
итоги и повторяющиеся запросы. JSON до 200 записей за раз, before/next_before
для всей истории. `/logs/search/replay?text=...` повторяет поиск без статистики
и без изменения карточек. Экспорт не содержит закрытого token и полного IP.
При закрытии публичной диагностики доступ остаётся у администратора.

Миграция hybrid_search создаёт журнал; release backup включает его. Сбой записи
диагностики не мешает выдаче/навигации и отмечается в серверном журнале.

## Код, демка и проверки

`involta_guide/search` — источник каталога, алгоритм, журнал; `web/routes/search.py`
— HTTP. `location-index.js` — прежний локальный индекс; `hybrid-search.js` — сеть,
кеш, смешивание и события; `location-search.js` — DOM/ARIA и морфинг. autoComplete.js
10.2.10 остаётся vendored без изменения, Apache-2.0, 9367 байт.

Админское добавление «Рядом» по-прежнему использует общий DOM-адаптер с локальным
каталогом id и защищённым POST. Гибридный публичный поиск к нему не подключается.

[Макет смешанной выдачи](design/hybrid-search/index.html) содержит тестовые названия;
production автоматически не меняется. Проверки покрывают сопоставление, видимость,
журнал/IP/позднюю доставку, отсутствие побуквенных запросов, кеш, устаревшие ответы,
клавиатуру/touch, морфинг, HTMX и переход к скрытой карточке ресторана.
