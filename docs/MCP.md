# Публичный MCP Инвольта гида

Владелец утвердил ровно два инструмента: `Location` и `Restaurant`. Отзывы входят
в их ответы. Отдельных инструментов поиска, отзывов, аналитики и администрирования нет.

## Подключение

- Endpoint: **https://involta.ru/guide/mcp**, без завершающего слэша.
- Streamable HTTP, официальный Python SDK `mcp==2.3.0`, JSON-ответы, stateless.
- Публичное чтение без токена, регистрации и cookies.
- Приложение включает MCP автоматически при старте; отдельный процесс не нужен.
- Все адреса строятся из `SITE_URL`/`BASE_PATH`. Примеры ниже — production-адреса
  после развёртывания соответствующего PR, а не утверждение о текущем релизе.

Пример конфигурации клиента с поддержкой удалённого MCP:

```json
{"mcpServers":{"involta-guide":{"url":"https://involta.ru/guide/mcp"}}}
```

Настройки конкретного клиента могут отличаться. Нужен удалённый Streamable HTTP,
а не локальный stdio-процесс. В OpenAI Responses API добавьте в `tools` вашего запроса:

```json
{
  "type": "mcp",
  "server_label": "involta_guide",
  "server_url": "https://involta.ru/guide/mcp",
  "allowed_tools": ["Location", "Restaurant"]
}
```

Политика подтверждения вызовов задаётся клиентом. Серверу credentials не нужны.
Сам MCP не вызывает OpenAI и не тратит AI-токены; подключённый ассистент оплачивается
по правилам выбранного пользователем приложения.

В ChatGPT: [Plugins](https://chatgpt.com/plugins) → «+» → **Add custom MCP server** →
публичный HTTPS endpoint выше → без авторизации → **Create as a plugin** → проверить
два инструмента. Затем установить/выбрать полученный плагин в разговоре. Возможность
добавления зависит от аккаунта и правил workspace. После изменения описаний/schema
нужно обновить подключение через Refresh и начать новый разговор.
[Официальная инструкция](https://developers.openai.com/plugins/deploy/connect-chatgpt).

## Поток

```text
ИИ-клиент → discover/initialize → tools/list
                                ├─ Location(location)
                                │    → точный публичный объект → подборка + отзывы
                                └─ Restaurant(restaurant_id)
                                     → опубликованная карточка

Guide MCP → существующие PostgreSQL-таблицы и current_content()
```

Оба инструмента помечены readOnly/idempotent/non-destructive/closed-world.
В описаниях сервера и JSON Schema есть назначение, входные параметры, форма ответа,
порядок использования, поведение при неоднозначности и ограничения отзывов.
SDK поддерживает современное обнаружение и совместимое initialize-подключение.
Возвращаются `structuredContent` и его JSON-представление в текстовом блоке.

### Location

```json
{"location":"Иваново"}
```

Также принимается `{"location":"ivanovo"}`. Обрезаются крайние пробелы,
игнорируются регистр и е/ё в названии. Это точное получение объекта: без морфологии,
опечаток, поиска по части названия или региону. Slug имеет приоритет перед названием.
Пустые значения и строки длиннее 200 символов отклоняются.

Ответ: `status=found|not_found|ambiguous`, `location`, `alternatives`, `message`.
Успешный `location` содержит:

- постоянный числовой `id`, canonical `location` (slug), название, тип, регион, URL;
- `content_status=published|not_filled|hub`, вступление, время редактирования;
- полные опубликованные карточки ресторанов в том же порядке, что на сайте;
- `reviews`: до 10 последних опубликованных непустых текстов, их ID/даты и общее
  количество доступных текстовых отзывов; ожидающие распознавания не считаются;
- только публичные активные дочерние и явно выбранные соседние локации.

Для одноимённых локаций возвращаются варианты с регионами и slug. Ассистент
уточняет выбор, затем повторяет Location с конкретным slug. Отсутствие совпадения
не заменяется «похожим» городом. Известные slug можно получить из существующего
`/guide/api/locations/catalogue` — это справочный JSON, не третий MCP-инструмент.

Видимая пустая локация возвращает `not_filled` без карточек и не запускает наполнение.
Надлокация `hub` возвращает публичных детей; собственной подборки у неё нет.

### Restaurant

```json
{"restaurant_id":"UUID из Location.location.restaurants[].id"}
```

Только стабильный UUID; название и числовой ID локации не подходят. Ответ:
`status=found|not_found`, `restaurant`, `message`. Карточка содержит название,
локацию, описание, кухню, телефон, карту, координаты, известные часы и источники.
Неизвестное значение — `null`; адрес не извлекается предположительно из карты.
Canonical URL ведёт к якорю `#restaurant-UUID` на странице локации.

Только активный ресторан опубликованной активной публичной обычной локации,
без состояния сброса. Прямое знание UUID не открывает скрытую карточку.
Место и внутренние оценки не хранятся заново: используется существующий порядок сайта.
Методология, ranking, служебные задания и административные поля не экспортируются.

В текущем публичном потоке нет достоверной привязки пользовательского отзыва
к ресторану. Поэтому `reviews={items:[],total:0,limit:10,status:"not_linked"}`.
У Location `reviews.status="available"`. Совпадение имени в тексте и старые
служебные предложения не считаются установленной привязкой.

## Обнаружение

- `/guide/for-agents` — индексируемая страница подключения в стилистике гида.
- `/guide/llms.txt` и `/guide/for-agents.md` — единая краткая инструкция в Markdown.
- `/guide/mcp-server.json` — манифест официального формата MCP Registry.
- Публичные HTML-страницы содержат ссылки `rel=help` на страницу подключения и
  `rel=alternate` на текстовую инструкцию. Видимый основной футер сохраняется.
- Страница подключения включена в sitemap. Endpoint MCP имеет `X-Robots-Tag: noindex`:
  поисковики должны индексировать документацию, а не POST JSON-RPC.

Guide размещён в подкаталоге `/guide`, поэтому инструкция лежит в этом же
подкаталоге. Корень `involta.ru` обслуживает другой сайт; этот PR не меняет его
nginx и не обещает несуществующий `/llms.txt` в корне домена.

`llms.txt` — подсказка для поддерживающих её агентов, а не обязательный стандарт
всех GPT. Страница и манифест позволяют обнаружить сервер; использовать инструменты
может только клиент, который подключил endpoint. Это не автоматическая установка
ChatGPT-приложения и не автоматическая публикация в каталоге ChatGPT.

После деплоя можно зарегистрировать сервер в MCP Registry. Манифест использует
namespace `io.github.involtax/involta-guide`, который требует подтверждения
GitHub-аккаунта involtax. С установленным официальным `mcp-publisher`:

```sh
curl --fail --silent --show-error https://involta.ru/guide/mcp-server.json -o server.json
mcp-publisher login github
mcp-publisher publish
```

Сначала проверяется доступность нового endpoint, затем выполняются авторизация
и публикация. Само размещение `server.json` не создаёт запись Registry.
Токены не коммитятся. Публикация в Registry и подключение к конкретным GPT-клиентам
проверяются отдельно и не выдаются за выполненные проверкой приложения.

## Границы и проверки

Операции выполняются в PostgreSQL-транзакциях `REPEATABLE READ, READ ONLY`:
карточки и их видимость читаются из согласованного снимка. Новых таблиц, очередей,
наполнений, AI-вызовов и фоновых задач нет. MCP не вызывает публичный поисковый POST,
не пишет search_attempts и не включает флаг audience_page. MCP-вызовы и документация
не увеличивают хиты/уники сайта и не устанавливают visitor-cookie.

Ограничение тела 16 KiB, параметры валидируются SDK/Pydantic. Host проверяется
по SITE_URL и локальным адресам, Origin при наличии — по origin сайта. Серверные
MCP-клиенты могут обращаться без Origin. Произвольные браузерные Origin не разрешены.
Ошибки не раскрывают SQL/credentials. Часы не выдумываются; updated_at означает
редактирование содержимого, а не проверку действительности заведения.

`tests/integration/test_mcp.py` проверяет оба режима согласования официальным
SDK по настоящему HTTP, schemas/annotations, карточки, публикацию, точное разрешение
названий, неоднозначность, тексты отзывов/порядок/лимит/total, отсутствие служебных
полей и записей в статистику/задания, неверные UUID/входные данные, Host/Origin,
ограничение тела, discovery-документы и нестандартный BASE_PATH.

Эталон страницы и скриншоты: [дизайн MCP](design/mcp/README.md).
