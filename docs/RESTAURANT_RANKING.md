# Единый рейтинг ресторанов

## Источник истины

`restaurants.ranking.scores` хранит восемь исходных оценок: food, consistency,
identity, localConnection, atmosphere, service, value, destination.
Каждая — целое число 0–10. Ноль является оценкой; отсутствие данных — нет.

Балл = сумма восьми оценок / 8, округление до двух знаков (`ROUND_HALF_UP`).
Если хотя бы одна оценка отсутствует/невалидна или набор критериев другой,
балл неизвестен. Не усреднять только заполненные оценки, не преобразовывать
строку/дробь/bool в целое, не подставлять ноль и не брать старый `totalScore`.

Текущий балл и место не хранятся: `position` удалён, `ranking.totalScore` удалён.
`restaurant_score` и `restaurant_rank_key` — общие функции сайта и админки.
Исторические баллы в отчёте запуска остаются диагностикой, не источником текущего
рейтинга. Удаление логов не меняет подборку.

## Порядок

1. Активные рестораны с полной оценкой: по баллу по убыванию.
2. Активные без полной оценки: после оценённых, включая рестораны с нулевым баллом.
3. При равенстве — по постоянному `restaurants.number` по возрастанию.
4. Неактивные доступны в админке после активных; публичного места у них нет.

Отзывы, их количество/оценки, звезда Алекса и название не являются дополнительными
критериями сортировки. Показываем их отдельно. Постоянный номер не равен месту.
Место вычисляется до пагинации и открытия отдельной карточки.

Состав активной подборки не меняется этим исправлением. Неоценённые рестораны
остаются после оценённых; отдельный статус «вне топа» не вводится. `top_limit` и
«Ещё» работают поверх того же порядка. Первичное наполнение по-прежнему требует
полных оценок для выбранных карточек; новые рестораны из отзывов могут быть без них.
Новые исследования публикуют все пригодные карточки; постоянные номера обеспечивают
стабильность при переименовании. Пересчёт не требует отдельного AI-запроса.
См. [независимые операции наполнения](INCREMENTAL_CONTENT.md).

## Переход и проверка

Миграция `canonical_rank` сохраняет рестораны, критерии, отзывы, логи и звёзды.
Удаляет только дублирующие вычисляемые поля. Старые миграции не переписываются:
у существующей БД должен быть однозначный путь вперёд. Перенаполнение не требуется.
Перед переходом deployment controller сохраняет приватный Guide dump; при сбое
восстанавливает схему/данные до запуска старого образа. См. BETA_CORE_RUNBOOK.md.

Тесты покрывают неполные/невалидные оценки, ноль, равенство, отсутствие влияния
звезды/отзывов, одинаковый порядок сайта/админки/карточки/пагинации, игнорирование
устаревшего отчёта, отсутствие изменений от перестановки входного списка и реальный
pg_dump → миграция → pg_restore. Браузерная проверка использует тестовые данные.
